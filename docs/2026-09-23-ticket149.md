### 5.1 Root Cause & Fix: Continue Webview Service Worker Failure
- **Observed Error**:
  ```text
  Error loading webview: Error: Could not register service worker: SecurityError: Failed to register a ServiceWorker for scope ('https://editor.titan.local/.../pre/') with script ('https://editor.titan.local/.../service-worker.js...'): An SSL certificate error occurred when fetching the script..
  ```
- **Root Cause**:
  - VS Code extension webviews (including Continue) run inside an `<iframe>` that registers a local Service Worker (`service-worker.js`) to intercept and serve webview assets.
  - Per the W3C Service Worker Specification and Chromium security policies, browsers strictly refuse to fetch or register Service Workers over HTTPS origins whose TLS certificate is self-signed/untrusted, even if the user clicked "Proceed to site (unsafe)" for document navigation.
  - In Ticket #145, testing was done via `http://editor.localhost` (or direct `http://localhost:8443`). Under RFC 6761 and Chromium standards, `*.localhost` origins are treated as secure contexts over plain HTTP with zero TLS certificate validation, which allowed the service worker to load seamlessly.
  - The Tool Egress Gateway (`mitmproxy`) is on `titan-internal` and is isolated from `code-server` (which runs on `titan-operator-net`), so egress proxying was not the cause.
- **Immediate Resolution**:
  - Access [http://editor.localhost](http://editor.localhost) directly. It operates in a secure context without SSL certificates and registers the Service Worker with zero errors.
  - For HTTPS on `https://editor.titan.local`: install `data/control_plane/caddy_root.crt` into the browser/system trust store (or add `https://editor.titan.local` to `chrome://flags/#unsafely-treat-insecure-origin-as-secure`).

### 5.2 Root Cause & Fix: "Unable to watch for file changes (error ENOSPC)"
- **Observed Error**:
  ```text
  Visual Studio Code is unable to watch for file changes in this large workspace (error ENOSPC)
  ```
- **Root Cause**:
  - The Linux kernel limits total inotify watch handles via `fs.inotify.max_user_watches` (default `65536` on the host).
  - Code-server previously did not exclude large database, logging, and build directories (`data/langfuse_clickhouse`, `data/langfuse_postgres`, `data/litellm_db`, `data/workspace`), exhausting all available inotify file handles.
- **Fix Applied**:
  - Added aggressive exclusion patterns for `**/data/langfuse_*/**`, `**/data/langfuse_clickhouse/**`, `**/data/langfuse_postgres/**`, `**/data/litellm_db/**`, `**/data/postgres/**`, `**/data/control_plane/**`, and `**/data/workspace/**` across `config/editor/settings.json`, `config/editor/titan.code-workspace`, `docker/editor/entrypoint.sh`, and live host settings.
  - **Permanent Host Setting**: To permanently raise kernel inotify watch limits on the host machine:
    ```bash
    echo fs.inotify.max_user_watches=524288 | sudo tee -a /etc/sysctl.conf && sudo sysctl -p
    ```
