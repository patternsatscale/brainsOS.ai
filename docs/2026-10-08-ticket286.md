# Ticket #286 Walkthrough: Isolate Hermes Runner Runtime State to Named Volume & Purge Spilled Artifacts

## Summary of Changes

This ticket resolves the issue where running the Hermes agent runner container (`runner-hermes`) spilled 787 ephemeral runtime files (downloaded lazy packages, bundled skills, session history, SQLite databases, and lockfiles) onto the host filesystem within the Git-tracked private fleet repository (`${BRAINSOS_DATA_DIR}/runners/hermes`).

### 1. `docker/compose/compose.agents.yml` & `docker-compose.yml`
- Replaced the direct host bind-mount of `${BRAINSOS_DATA_DIR}/runners/hermes` to `/opt/data` with a dedicated persistent named volume: `hermes_runner_data` (`brainsos_hermes_runner_data`).
- Mounted static runner configuration files individually from the host into `/opt/data`:
  - `${BRAINSOS_RUNNERS_DIR}/hermes/config.yaml:/opt/data/config.yaml:rw`
  - `${BRAINSOS_RUNNERS_DIR}/hermes/config.json:/opt/data/config.json:ro`
  - `${BRAINSOS_RUNNERS_DIR}/hermes/model_pool.json:/opt/data/model_pool.json:ro`
  - `${BRAINSOS_RUNNERS_DIR}/hermes/mcp.json:/opt/data/mcp.json:ro`
- Declared `hermes_runner_data` under `volumes:` in both `compose.agents.yml` and `docker-compose.yml`.

### 2. `config/templates/data-repo.gitignore` & `${BRAINSOS_DATA_DIR}/.gitignore`
- Added comprehensive ignore rules for Hermes runner runtime artifacts:
  - Dynamic packages: `runners/hermes/lazy-packages/`
  - Dynamic tool skills: `runners/hermes/skills/`
  - Caches: `cache/`, `audio_cache/`, `image_cache/`
  - Logs, sessions, state, cron, kanban: `logs/`, `sessions/`, `state/`, `cron/`, `kanban/`, `sandboxes/`, `platforms/`
  - Transients & locks: `*.lock`, `.*.lock`, `*.pid`, `*.sock`, `*.log`, `*.bak*`, `.env*`, `install_id*`, `gateway_state.json`, etc.

### 3. Cleaned Local Fleet State (`brainsOS/data`)
- Purged all untracked spilled runtime artifacts from the host's `runners/hermes/` directory.
- `git status` in `${BRAINSOS_DATA_DIR}` dropped from **802 pending changes down to 15** (strictly intentional memory files and config edits).
