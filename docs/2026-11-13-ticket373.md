## 1. Summary of Changes

### Files Created
- [`scripts/control/sync-route53-ddns.py`](file:///home/patternsatscale/brainsOS/os/scripts/control/sync-route53-ddns.py): Host-only Route 53 Dynamic DNS synchronizer using `/opt/brainsos/.venv/bin/python` + `boto3` (zero `awscli` bloat, zero container IMDS exposure). Performs idempotent `UPSERT` of the appliance `A` record (`TTL=60`) and a companion `_brainsos-owner.<fqdn>` `TXT` (`"instance-id=<id>"`) ownership lock to prevent cross-instance DNS hijacking unless `--force` / `BRAINSOS_ROUTE53_FORCE=true` is passed. Gracefully falls back to direct `ChangeResourceRecordSets` if the attached IAM role omits `ListResourceRecordSets`.
- [`packages/brainsOS-appliance/iam/route53-ddns-policy.json`](file:///home/patternsatscale/brainsOS/os/packages/brainsOS-appliance/iam/route53-ddns-policy.json): Least-privilege IAM policy template scoping `route53:ChangeResourceRecordSets` and `route53:ListResourceRecordSets` to a single Hosted Zone and wildcard subdomain pattern (`*.demo.infotechlabs.io`).
- [`packages/brainsOS-appliance/tests/test_route53_ddns.py`](file:///home/patternsatscale/brainsOS/os/packages/brainsOS-appliance/tests/test_route53_ddns.py): Unit and integration test suite covering `sync-route53-ddns.py` (`UPSERT`, unchanged no-op, cross-instance collision exit `2`, `--force` override, minimal IAM `AccessDenied` fallback, auto-zone discovery, invalid input rejection) and `firstboot.sh --dry-run` User Data scenarios.
- [`docs/2026-11-13-ticket373.md`](file:///home/patternsatscale/brainsOS/os/docs/2026-11-13-ticket373.md): This ticket walkthrough.

### Files Modified
- [`packages/brainsOS-appliance/scripts/firstboot.sh`](file:///home/patternsatscale/brainsOS/os/packages/brainsOS-appliance/scripts/firstboot.sh):
  - Parses `BRAINSOS_ROUTE53_ZONE_ID` / `HOSTED_ZONE_ID` / `route53_zone_id` (including full `arn:aws:route53:::hostedzone/Z...` ARNs), `RECORD_NAME`, `BRAINSOS_BASE_DOMAIN` / `base_domain`, and `BRAINSOS_ROUTE53_FORCE` / `route53_force` from EC2 User Data, plus EC2 `tags/instance/Name` via IMDSv2.
  - Supports both per-instance `BRAINSOS_DOMAIN=alice.demo.infotechlabs.io` and shared Launch Template `BRAINSOS_BASE_DOMAIN=demo.infotechlabs.io` (auto-deriving `<name-tag>.demo.infotechlabs.io` or `<short-instance-id>.demo.infotechlabs.io`).
  - Defaults `BRAINSOS_TLS_MODE=acme` and `ACME_EMAIL=ops@<apex>` when Route 53 + custom domain is supplied, runs `sync-route53-ddns.py` on cold boot before Caddy starts (with `<short-instance-id>` fallback on collision RC `2`), and persists `BRAINSOS_USERDATA_ROUTING=true`, `BRAINSOS_ROUTE53_ZONE_ID`, `BRAINSOS_ROUTE53_FORCE`, and `BRAINSOS_LAST_SYNCED_IP` in `.env`.
- [`scripts/control/reload-env.sh`](file:///home/patternsatscale/brainsOS/os/scripts/control/reload-env.sh):
  - Extended Step `0b` (invoked on every boot by `brainsos.service` and on every hibernation wake-up by `brainsos-resume.service`) to automatically re-run `sync-route53-ddns.py` whenever `public-ipv4` changes on a custom Route 53 domain and update `BRAINSOS_LAST_SYNCED_IP`.
- [`packages/brainsOS-telemetry/brainsos_telemetry/system.py`](file:///home/patternsatscale/brainsOS/os/packages/brainsOS-telemetry/brainsos_telemetry/system.py) & [`packages/brainsOS-telemetry/tests/test_system_api.py`](file:///home/patternsatscale/brainsOS/os/packages/brainsOS-telemetry/tests/test_system_api.py):
  - Exposes `userdata_routing_configured` and `route53_zone_id` on `/api/v1/system/identity` and `/api/v1/system/status`.
  - Preserves User-Data `url`, `local_domain`, `tls_mode`, and `acme_email` during `/api/v1/system/setup` when `userdata_routing_configured` is `True`.
- [`packages/brainsOS-portal/src/components/SystemManager.tsx`](file:///home/patternsatscale/brainsOS/os/packages/brainsOS-portal/src/components/SystemManager.tsx) & [`packages/brainsOS-portal/src/App.tsx`](file:///home/patternsatscale/brainsOS/os/packages/brainsOS-portal/src/App.tsx):
  - Prevents `handleSuperuserFullNameChange` and `handleSuperuserUsernameChange` from clobbering `setupLocalDomain` (`alice.demo.infotechlabs.io`) with `*.aws.cloud.brainsos.ai` when `userdata_routing_configured` is `true`.
  - Streamlines the First-Boot Setup Wizard into a **2-step flow** (`STEP 1 OF 2: Create Superuser Account`, `STEP 2 OF 2: Unit Identity & SSL Summary`) with a read-only **Launch Routing, Custom DNS & SSL** summary card and **Let's Encrypt TLS Active** header badge when `userdata_routing_configured` is `true`, while keeping the full 3-step Wizard intact when `userdata_routing_configured` is `false`.
- [`.env.example`](file:///home/patternsatscale/brainsOS/os/.env.example), [`README.md`](file:///home/patternsatscale/brainsOS/os/README.md), and [`packages/brainsOS-appliance/README.md`](file:///home/patternsatscale/brainsOS/os/packages/brainsOS-appliance/README.md): Documented `BRAINSOS_ROUTE53_ZONE_ID`, `BRAINSOS_BASE_DOMAIN`, `BRAINSOS_ROUTE53_FORCE`, and `BRAINSOS_USERDATA_ROUTING`.
