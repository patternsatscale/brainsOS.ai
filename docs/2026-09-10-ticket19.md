## 2. Acceptance Criteria Verification

- [x] **Decoupled execution on remote machine**: `docker/langfuse/docker-compose.yml` and `scripts/setup-langfuse.sh` can be copied to or run on any remote machine/laptop on the LAN.
- [x] **No auto-start by default on GX10**: `LANGFUSE_AUTO_START=false` by default in `.env`. Core Titan services start without launching Langfuse unless explicitly started or configured.
- [x] **Configurable auto-start in `.env`**: `LANGFUSE_AUTO_START` parameter controls automated start in `scripts/start-control-plane.sh`.
- [x] **Dedicated Port Allocation (Port 3001)**: Dedicated port 3001 assigned to Langfuse, cleanly separating it from SilverBullet (Port 3000) and avoiding any port collisions or complex detection workarounds.
- [x] **Standardized DNS (`langfuse.titan.local`)**: Configured in `/etc/hosts` via `scripts/setup-network.sh`, routed in Caddy, and mapped inside Hermes container via `extra_hosts`.
- [x] **Hermes OpenTelemetry ingestion**: Configured in `config/hermes/config.yaml` to push OTLP traces to `http://langfuse.titan.local:3001/api/public/otel/v1/traces`.
- [x] **LiteLLM OpenTelemetry & trace ingestion**: Integrated via dynamic callbacks (`langfuse` + `otel`) and environment variable configuration in `scripts/start-control-plane.sh`.
- [x] **Rule 1 (Memory Plane Purity)**: Zero SQLite/trace artifacts written to `/memories`.
- [x] **Rule 6 (Database Isolation)**: Langfuse uses `titan-langfuse-db` on `titan-langfuse-net`; LiteLLM database `titan-litellm-db` remains strictly isolated.
- [x] **Rule 7 (Information Compartmentalization)**: No host database passwords or raw inference topology exposed to Hermes.
- [x] **Rule 8 (Script-Driven Discipline)**: Zero ad-hoc container patching; all lifecycle actions codified in `scripts/setup-langfuse.sh` and verified in `scripts/verify-langfuse.sh`.

## 4. How to Operate Langfuse on a Remote Laptop

1. **On your remote laptop**:
   Clone or copy `docker/langfuse/` and `scripts/setup-langfuse.sh`.
   Run:
   ```bash
   ./scripts/setup-langfuse.sh setup
   ./scripts/setup-langfuse.sh start
   ```
   Open `http://localhost:3001` in your browser, create the admin account, create a Project, and generate an API key pair (`pk-lf-...` and `sk-lf-...`).

2. **On the GX10 Appliance**:
   Run the interactive keys helper to compute the OTel Basic authorization header:
   ```bash
   ./scripts/setup-langfuse.sh keys
   ```
   Update `.env`:
   ```bash
   LANGFUSE_HOST_IP=<ip-of-your-laptop>
   LANGFUSE_HOST=http://langfuse.titan.local:3001
   LANGFUSE_PUBLIC_KEY=pk-lf-...
   LANGFUSE_SECRET_KEY=sk-lf-...
   LANGFUSE_OTEL_AUTH=Basic ...
   ```
   Update host DNS:
   ```bash
   sudo ./scripts/setup-network.sh --langfuse-ip <ip-of-your-laptop>
   ```
   Restart the control plane:
   ```bash
   ./scripts/start-control-plane.sh restart
   ```
