# Walkthrough - Ticket #274: Hardening Fresh Install Setup, Runner Base Build & Control Plane Resilience

## Overview
During the initial execution of `make setup`, `make env`, and `make test` on a fresh system, several issues were uncovered and resolved:

1. **Local Inter-Package Dependency Resolution**:
   - `scripts/control/bootstrap-env.sh` installed local packages in `packages/` one-by-one in alphabetical order via `uv pip install -e "${pkg}"`. Sibling dependencies (e.g. `brainsOS-agent` depending on `brainsos-mail>=0.1.0`) failed because sibling packages were not yet installed and are not on PyPI.
   - *Fix*: Aggregated all package targets (`-e <path>`) into `pkg_args=()` for a single atomic `uv pip install` / `pip install` invocation.
   - *Fix*: Removed invalid bash `local` keyword outside of a function.

2. **Testing & Control Plane Python Dependencies**:
   - `make test` failed during test collection for `packages/brainsOS-mcp` due to missing `tiktoken`.
   - Host LiteLLM gateway and Prisma failed because `litellm[proxy]`, `prisma`, `langfuse`, and `opentelemetry` were not installed in `.venv` during bootstrap, and Prisma client bindings were ungenerated.
   - *Fix*: Added `tiktoken`, `litellm[proxy]`, `prisma`, `langfuse>=2.0.0,<3.0.0`, `opentelemetry-api`, `opentelemetry-sdk`, and `opentelemetry-exporter-otlp` to `.venv` installation in `bootstrap-env.sh`, and pre-generated Prisma client Python bindings.

3. **Base Runner Image Missing on Fresh Install**:
   - `runner-hermes`, `runner-openai`, and `runner-claude` inherit `FROM brainsos-runner-base:latest`.
   - When running `make env` (which invokes `reload-env.sh` -> `docker compose up -d`) or `make up` on a fresh machine where `runner-base` has not yet been built, Docker Compose attempted to pull `brainsos-runner-base:latest` from Docker Hub and failed with `pull access denied`.
   - *Fix*: Added a check in `scripts/control/reload-env.sh` to automatically build `brainsos-runner-base:latest` if missing. Updated `Makefile` so `up: runner-base`.

4. **Tool Egress Proxy mitmweb Password Escaping**:
   - In `docker-compose.yml`, `--set web_password=$${TOOL_EGRESS_WEB_PASSWORD...}` used double `$$`, passing literal `$TOOL_EGRESS_WEB_PASSWORD` into `mitmweb`. `mitmweb` rejected it because passwords starting with `$` are reserved for argon2 hashes.
   - *Fix*: Changed to single `${TOOL_EGRESS_WEB_PASSWORD:-...}` so the resolved password string is passed directly.

5. **Caddy Root CA Trust Extraction Syntax Error**:
   - `scripts/setup/trust-caddy-ca.sh` contained an unclosed `for attempt in 1 2 3 4 5; do` loop missing a `done`, causing a bash syntax error.
   - *Fix*: Added `done` to properly close the retry loop.

6. **LiteLLM SSL Crash on Empty CA Placeholder**:
   - `scripts/control/start-control-plane.sh` exported `SSL_CERT_FILE="${CADDY_CA_FILE}"` even when `caddy_root.crt` was a 0-byte placeholder touched during initial bootstrap, causing Python's `ssl.create_default_context` to crash with `[X509: NO_CERTIFICATE_OR_CRL_FOUND]`.
   - *Fix*: Conditioned `SSL_CERT_FILE` and `REQUESTS_CA_BUNDLE` on `[ -s "${CADDY_CA_FILE}" ]` so empty placeholders are ignored.

7. **Runner Service Naming Consistency**:
   - `scripts/control/start-control-plane.sh` referenced `hermes-runner` in `docker compose ps` and `docker compose up`, but the service in `docker-compose.yml` is `runner-hermes`.
   - *Fix*: Standardized on `runner-hermes`.

8. **Operator IDE & Authentik Directory Ownership & Inheritance**:
   - In `.env.example`, `BRAINSOS_CODE_SERVER_CONFIG` and `BRAINSOS_CODE_SERVER_DATA` were hardcoded to `./data/...` instead of inheriting from `BRAINSOS_DATA_DIR`.
   - `bootstrap-env.sh` omitted `authentik_db`, `authentik_media`, and `comms/sogo` from `DATA_DIRS`, causing Docker daemon to auto-create them as `root:root 755` and triggering permission errors for containers running as uid 1000.
   - *Fix*: Commented out `BRAINSOS_CODE_SERVER_*` in `.env.example` to inherit from `BRAINSOS_DATA_DIR`, and added all runtime mount paths (`authentik_media`, `authentik_db`, `comms/sogo/*`, `comms/email/*`, `comms/signal`) to `DATA_DIRS` in `bootstrap-env.sh`.

9. **Turnkey `make setup` Execution**:
   - Previously, `make setup` only scaffolded storage directories and installed Python packages without generating `.env`, compiling the React portal SPA, building the base runner image, or pre-compiling Docker images.
   - *Fix*: Enhanced `scripts/control/bootstrap-env.sh` and `Makefile` to make `make setup` a complete turnkey bootstrap command:
     - Generates cryptographically secure `.env` via `generate-env.sh --defaults --no-rebuild` if `.env` is absent, while preserving existing `.env` and supporting `--data-dir <path>`.
     - Expands tilde (`~`) paths cleanly.
     - Pre-creates `packages/brainsOS-portal/dist` under the host user's UID to prevent Docker daemon from creating it as root.
     - Builds the portal React SPA bundle via `setup-portal.sh` or npm.
     - Builds `brainsos-runner-base:latest`, burns Hermes runner config, and executes `docker compose build` for all platform images.
     - Added `make build` and `make images` targets to `Makefile`.

10. **Appliance Host Identity (`dgx.local.brainsos.ai`) & Authentik Outpost Sync**:
    - The appliance host identity on ASUS Ascent GX10 is `dgx.local.brainsos.ai` (`BRAINSOS_DOMAIN=dgx.local.brainsos.ai`), serving the brainsOS Web Portal & Authentik SSO Ingress (distinct from the native NVIDIA DGX Telemetry Dashboard service running on port 11000/11001).
    - When unconfigured or referencing legacy `osx.local.brainsos.ai`, Authentik's embedded proxy outpost generated relative redirects to `http://0.0.0.0:9000/application/o/authorize/...`, causing browser connection refused errors.
    - *Fix*: Codified dynamic domain synchronization in both `scripts/control/reload-env.sh` and `scripts/setup/setup-portal.sh`. Authentik's embedded Outpost `_config` (`authentik_host` & `authentik_host_browser`), `ProxyProvider` (`external_host`, `cookie_domain`, `redirect_uris`), and `Application` `meta_launch_url` dynamically synchronize with `${BRAINSOS_DOMAIN}` on setup and reload.
    - *Fix*: Verified Caddy reverse proxy correctly routes `https://dgx.local.brainsos.ai/` to the Authentik SSO flow and brainsOS thin-spine React SPA, while the NVIDIA DGX Dashboard is accessible via Authentik forward-auth under `https://dgx.local.brainsos.ai/dgx/` (and bridged locally on `172.17.0.1:11001`).

11. **Public Wildcard SSL via AWS Route 53 ACME DNS-01 (`*.local.brainsos.ai`)**:
    - To eliminate browser SSL warnings on developer workstations (macOS, iOS, Windows, Linux) without requiring manual self-signed certificate imports into OS keychains, brainsOS supports automated ACME DNS-01 challenge issuance via AWS Route 53.
    - *Fix*: Enhanced `scripts/control/reload-env.sh` to dynamically compile `config/caddy/tls_policy.caddy` when `ACME_DNS_PROVIDER=route53`. Configured 30s propagation delay, 3m timeout, external resolvers (`1.1.1.1 8.8.8.8`), and automatic AWS credentials resolution from host AWS CLI (`aws configure get`).
    - *Fix*: Successfully verified and issued a public wildcard certificate for `*.local.brainsos.ai` signed by ZeroSSL / Let's Encrypt, verified with strict TLS (`curl -Iv https://dgx.local.brainsos.ai/`).

12. **LiteLLM Combined CA Bundle & Startup Resilience**:
    - Previously, setting `SSL_CERT_FILE="${CADDY_CA_FILE}"` wiped out Python's default CA bundle, causing LiteLLM to fail HTTPS requests to GitHub (retrying 3 times to fetch model pricing maps) and external model APIs with `[SSL: CERTIFICATE_VERIFY_FAILED]`.
    - *Fix*: Updated `scripts/control/start-control-plane.sh` to construct a combined CA bundle concatenating `certifi` system roots with any local Caddy CA certificate into `${PID_DIR}/combined_ca.pem`. This guarantees internal Authentik SSO calls pass while external model APIs and GitHub pricing maps succeed with zero latency.
