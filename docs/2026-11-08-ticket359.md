## 1. Summary of Changes

### A. Editable Markdown Onboarding Seed Emails (`config/default_emails/*.md` & `scripts/control/send-welcome-email.py`)
- Extracted the onboarding email suite out of hardcoded Python strings into 7 human-editable Markdown templates with YAML-style frontmatter in `config/default_emails/` (with live override support via `${BRAINSOS_DATA_DIR}/settings/emails/*.md` or `BRAINSOS_EMAIL_TEMPLATES_DIR`):
  1. `config/default_emails/00-release-candidate-notice.md` — Ephemeral 7-day Release Candidate notice and bug/feature reporting instructions.
  2. `config/default_emails/01-30min-demo-script.md` — 30-minute member meeting run-of-show playbook with pre-flight container update reminder and live Bawtford research script.
  3. `config/default_emails/02-bawtford-intro.md` — Introduction from **Bawtford**, Chief Paw-ficer, Digital Manager & Tech Lead to **Cindy Pawford** (`cindypawford.com`).
  4. `config/default_emails/03-field-guide.md` — 5-step Initial Setup & First-Flight Checklist (update containers in System Manager, run self-research prompt on Bawtford, inspect Egress Proxy, LiteLLM, Langfuse, and `/memories`).
  5. `config/default_emails/04-zero-trust-guardrails.md` — Tour of the zero-trust defense layers (`Alt+2` Authentik, `Alt+3` LiteLLM, `Alt+4` Langfuse, `Alt+5` Egress Proxy).
  6. `config/default_emails/05-readable-memory-git.md` — Tour of Rule 1 (`/memories` OKF Markdown purity), `Alt+6` Code Console, and `Alt+7` Gitea version control.
  7. `config/default_emails/06-appliance-cheat-sheet.md` — Operator cheat sheet with `"Welcome to Your Sovereign AI Operating System"` subject, 7-layer hotkey directory, and upstream open-source product attribution links (`SOGo`, `Postfix/Dovecot`, `Authentik`, `LiteLLM`, `Langfuse`, `mitmproxy`, `code-server`, `Gitea`, `Caddy`, `XTerm.js`, `Hermes Agent`, `Ollama`, `PostgreSQL`, `ClickHouse`, `Redis`, `MinIO`).
- Updated `scripts/control/send-welcome-email.py` to parse frontmatter and Markdown bodies into both plain-text and dark-mode HTML multipart emails with dynamic template variable substitution (`{domain}`, `{local_domain}`, `{user}`, `{base_url}`, `{unit_name}`).

### B. Help Menu — `Architecture` & `Bugs & Features` Tabs (`packages/brainsOS-portal/src/components/HelpView.tsx`)
- Added upstream open-source product attribution links (`Powered by ...`) to each subsystem card on the **Tool URLs** tab.
- Added the **Architecture** tab featuring:
  1. **Enterprise Agent in a Box — 7-Layer Request Flow** (`L1` Secure Communications → `L7` Source Control)
  2. **Zero-Trust Docker Network Isolation (5 Planes)** (`brainsos-ingress-net`, `brainsos-control-net`, `brainsos-internal-net`, `brainsos-ide-net`, `brainsos-telemetry-net`)
  3. **Core Architectural Guardrails** (Memory Plane Purity, In-Transit Egress Auth, Unified Memory Protection)
- Added the **Bugs & Features** tab with 1-click links to GitHub Issue templates (`bug_report.md`, `feature_request.md`) and an interactive **Quick GitHub Issue Composer** that pre-fills title, labels, subsystem metadata, and Markdown body on `github.com/patternsatscale/brainsOS.ai/issues/new`.

### C. XTerm PTY Controlling Terminal (`TIOCSCTTY`) Fix & Welcome Banner (`packages/brainsOS-telemetry/brainsos_telemetry/system.py`)
- Attached the PTY slave FD as the session's controlling terminal (`fcntl.ioctl(0, termios.TIOCSCTTY, 0)` immediately after `os.setsid()` in `_preexec()`) and configured initial PTY window geometry (`TIOCSWINSZ`), eliminating `bash: cannot set terminal process group (-1): Inappropriate ioctl for device` and enabling shell job control.
- Replaced the single-line header with a clean welcome banner displaying quick-reference operator commands.

### D. Per-Agent Virtual Key Attribution (`docker/compose/compose.agents.yml` & `docker/hermes/plugins/model-providers/brainsos-litellm-session/__init__.py`)
- Passed `BAWTFORD_LITELLM_KEY`, `TERRASTELLA_LITELLM_KEY`, and `MARVIN_LITELLM_KEY` into `runner-hermes` and defaulted `OPENAI_API_KEY` to `${BAWTFORD_LITELLM_KEY}`.
- Updated `BrainsOSLiteLLMSessionProfile.build_api_kwargs_extras` to dynamically resolve the tenant virtual key from `session_id` (`mail-bawtford-...`, `mail-terrastella-...`, `mail-marvin-...`) and attach `extra_headers: {"Authorization": "Bearer <vkey>"}` so LiteLLM logs all agent completions under their respective virtual keys (`brainsos-bawtford`, `brainsos-terrastella`, `brainsos-marvin`).

### E. Code-Server Session Chat GitHub Sign-In Suppression (`docker/editor/Dockerfile`, `docker/editor/entrypoint.sh`, `config/editor/settings.json`, `config/editor/extensions/brainsos-system-terminal/extension.js`)
- Patched `/usr/lib/code-server/lib/vscode/extensions/copilot/package.json` at image build time to clear `.contributes.chatViewsWelcome` and `.contributes.chatSessions`.
- Enabled `"chat.allowAnonymousAccess": true` and disabled `copilotcli` / `cloudAgent` harnesses.
- Mirrored `chatLanguageModels.json` into the browser workbench's `vscode-userdata:/User/chatLanguageModels.json` and asserted BYOK context keys in `brainsos-system-terminal/extension.js`.
- Updated `reload-env.sh` and `start-control-plane.sh` to recreate `code-server` when `OPERATOR_LITELLM_KEY` is provisioned, plus added a background retry loop in `docker/editor/entrypoint.sh`.
