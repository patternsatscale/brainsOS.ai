# Walkthrough - Ticket #270: Add Containerized LiteLLM Service & Internal Bridge Networking to Compose

## 1. Overview
Ticket #270 is the foundational infrastructure deliverable under **Epic #273** (*Containerize LiteLLM Control Plane Gateway & Hardened Database Isolation*). This change migrates the LiteLLM proxy gateway into a containerized service within `docker-compose.yml` (`ghcr.io/berriai/litellm-database:main-latest`), attaches it to both `brainsos-litellm-net` (for PostgreSQL access) and `brainsos-internal` (for Caddy ingress and agent plane communication), and hardens **Rule 6 (Database Isolation)** by eliminating the host loopback port mapping `127.0.0.1:5432:5432` from `brainsos-infra-litellm-db`.

---

## 2. Summary of Changes

### A. Infrastructure & Topology (`docker-compose.yml`)
- **Added `litellm` service (`brainsos-infra-litellm`)**:
  - Image: `ghcr.io/berriai/litellm-database:main-latest`.
  - Security Profile: `no-new-privileges:true`.
  - Port mapping: `127.0.0.1:${LITELLM_PORT:-4000}:4000`.
  - Upstream routing: `host.docker.internal:${DOCKER_HOST_GATEWAY:-host-gateway}`.
  - Volumes:
    - `${LITELLM_CONFIG:-./config/litellm/config.yaml}:/app/config.yaml:ro`
    - `${BRAINSOS_CONTROL_PLANE_DIR:-${BRAINSOS_DATA_DIR:-./data}/control_plane}/caddy_root.crt:/etc/ssl/caddy/root.crt:ro`
  - Environment: Configured `DATABASE_URL` pointing to `litellm-db:5432` over private bridge, `STORE_MODEL_IN_DB=True`, CA bundle paths, and master keys.
  - Networks: Attached to `brainsos-litellm-net` and `brainsos-internal` (aliases: `litellm`, `brainsos-litellm`).
  - Healthcheck: Python liveness probe on `http://127.0.0.1:4000/health/liveness`.
- **Hardened `litellm-db` (`brainsos-infra-litellm-db`)**:
  - Removed host port mapping `127.0.0.1:${LITELLM_DB_PORT:-5432}:5432`.
  - Service now communicates strictly and exclusively across the internal `brainsos-litellm-net` bridge with `litellm`.
- **Pruned `code-server` `extra_hosts`**:
  - Removed obsolete `litellm:host-gateway` alias that was intercepting Docker internal DNS routing.

### B. Gateway Configuration (`config/litellm/config.yaml`)
- Parameterized `api_base` across all defined model configurations (`brainsos-core`, `qwen3.8:latest`, `llama3.2:3b`, `qwen2.5:latest`, `cindy-active-coding-model`, `gemma2:2b`) to use `os.environ/OLLAMA_API_BASE` (defaulting to `http://host.docker.internal:11434`), supporting both local host inference and containerized gateways.

### C. Ingress Routing (`config/caddy/Caddyfile`)
- Migrated 13 reverse proxy handlers from `reverse_proxy host.docker.internal:4000` to `reverse_proxy {$LITELLM_UPSTREAM:litellm:4000}`, enabling direct container-to-container routing over `brainsos-internal` while preserving variable override capability.
- Normalized UI redirects: Added trailing slash to `@proxy_ui_defaults` (`/proxy/ui/usage/`), preventing upstream Starlette static directory redirects from downgrading HTTPS requests to HTTP.
- Hardened iFrame embedding: Added `header_down -x-frame-options` and `header_down -content-security-policy` across `/litellm-asset-prefix/*` and `/.well-known/litellm-ui-config` routes to ensure portal viewports and embedders can load Next.js assets unhindered.

### D. Portal UI Integration (`packages/brainsOS-portal`)
- Updated `subsystems.ts` and `ViewportFrame.tsx` to set the security subsystem title directly to **"LiteLLM"** and route to `/proxy/ui/usage/`.
- Recompiled portal SPA bundle (`npm run build`) into `packages/brainsOS-portal/dist`.

### E. Architectural Documentation (`README.md` & `AGENTS.md`)
- Updated `README.md` Mermaid topology diagram to reflect that PostgreSQL Control DB has zero host port bindings.
- Updated `AGENTS.md` Rule 6 specification to reflect hardened network isolation over `brainsos-litellm-net`.

### F. Scripted Admin Role Provisioning (`scripts/setup/setup-litellm-sso.sh`)
- Created idempotent script `scripts/setup/setup-litellm-sso.sh` managing admin identities via LiteLLM REST API:
  - Provisions admin identities (`admin@${BRAINSOS_DOMAIN}`, `admin@dgx`, `admin@osx.local.brainsos.ai`, `admin`) with `user_role: "proxy_admin"` and `models: ["all-proxy-models"]`.
  - Separates initial creation (`POST /user/new`) from credential configuration (`POST /user/update`) to adhere to LiteLLM REST API schema constraints.
  - Updates generic SSO role mappings via `PATCH /update/sso_settings` while supplying full OIDC endpoints and credentials so settings are preserved rather than cleared to `null`.
  - Suppresses environment-credential login warnings (`disable_env_credential_login: true`).

## 5. Differential SSO Diagnosis & Implementation Summary
Following collaboration between the macOS development machine and the Linux appliance, the following 7 runtime parity and bootstrap fixes were codified and verified:
1. **Network Parity**: Attached `litellm` to `brainsos-ingress` so the container can exchange OAuth tokens directly with `authentik-server:9000`.
2. **Admin Privilege Preservation**: Removed `default_role: internal_user` and provisioned custom ScopeMapping `litellm_groups_mapping` in `config/authentik/blueprints/brainsos-portal.yaml` to prevent automatic demotion of administrator sessions.
3. **Safety Fallback Alignment**: Set `PROXY_ADMIN_ID=${BRAINSOS_ADMIN_USERNAME:-admin}` to match Authentik's `preferred_username`.
4. **Wildcard Redirect URIs**: Configured regex patterns in `brainsos-portal.yaml` supporting both `dgx.local.brainsos.ai` and `osx.local.brainsos.ai`.
5. **Database Bundle Upgrade**: Switched image to `ghcr.io/berriai/litellm-database:main-latest` for Prisma migration and PostgreSQL operational stability.
6. **Auxiliary Guardrail**: Enforced `profiles: ["mail-ingress"]` in `docker-compose.yml` and log rotation (`max-size: 10m`) to prevent unconfigured daemons from consuming host disk resources.
7. **REST API Parameter Preservation**: Updated `scripts/setup/setup-litellm-sso.sh` to include all OIDC endpoint credentials in `PATCH /update/sso_settings` payloads (preventing LiteLLM from overwriting env-configured OIDC endpoints to `null`), and decoupled `POST /user/new` from password assignment.
8. **Model Leaderboard Ingress Routing**: Expanded `@litellm_api` and `@proxy_litellm_api` route matchers in `config/caddy/Caddyfile` to include `/model*` (and related management paths), ensuring `/model-insights` and `/proxy/model-insights` return JSON data rather than falling through to the portal's `index.html` fallback.

All changes verified with complete parity on both the production DGX OS appliance and the local Apple Silicon macOS development environment.
