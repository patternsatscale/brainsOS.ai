# Ticket #297 Walkthrough: Cross-Platform Portability (amd64 / arm64) & Hermes Runner Build Fix

## Summary of Changes

This ticket resolves upstream container path issues and shell divergences across **macOS workstations (osx / Apple Silicon / Intel)** and **Linux appliances (dgx / ASUS Ascent GX10 / Ubuntu 24.04)**:

1. **Hermes Runner Container (`runner-hermes`) `uv` Resolution**:
   - In upstream `nousresearch/hermes-agent:latest`, Astral's `uv` binary is installed in `/opt/hermes/tools/uv-*/uv` rather than in standard `$PATH` (`/usr/local/bin/uv`).
   - During `make setup` and `docker compose build runner-hermes`, the build previously errored with `/bin/sh: 1: /usr/local/bin/uv: not found`.
   - Updated `docker/hermes/Dockerfile` to dynamically locate and symlink `uv` from `/opt/hermes/tools` into `/usr/local/bin/uv` and `/bin/uv`, with an automatic fallback to Astral's official installer (`https://astral.sh/uv/install.sh`).
   - Verified that `nousresearch/hermes-agent:latest` contains multi-platform manifests for both `linux/amd64` and `linux/arm64`, and that the dynamic search finds the platform-native binary (`uv-*-linux-x64/uv` on amd64 and `uv-*-linux-arm64/uv` on arm64).

2. **Cross-Platform `sed -i` Portability**:
   - `scripts/setup/link-signal.sh`: Replaced GNU-only `sed -i` (which failed on macOS BSD `sed`) with POSIX-standard `sed -i.bak ... && rm -f ...bak`.
   - `scripts/apps/cindypawford/republish-archives.sh`: Replaced BSD-only `sed -i ''` (which failed on Linux GNU `sed`) with POSIX-standard `sed -i.bak ... && rm -f ...bak`.

3. **Dynamic Stage & Appliance Prefix Detection**:
   - `scripts/control/generate-env.sh`: Automatically detects the host operating system (`sys.platform == "darwin"`), setting `BRAINSOS_STAGE=osx` on macOS workstations and `BRAINSOS_STAGE=dgx` on Linux/DGX appliances.
   - `scripts/setup/setup-wildcard-ssl.sh`: Defaults `APPLIANCE_PREFIX` adaptively (`osx` on macOS workstations, `dgx` on appliances) rather than hardcoding `dgx`.

4. **Robust Binary Discovery in Bootstrap**:
   - `scripts/control/bootstrap-env.sh`: Injects standard user and system binary paths (`~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`) into `$PATH` at startup, ensuring `uv` and `python3` are always discoverable across macOS and Linux non-interactive shell environments.
