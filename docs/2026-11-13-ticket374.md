## 1. Summary of Changes

To cut Golden AMI build cycles from **~40 minutes down to ~5 minutes** for iterative releases while preserving clean-room artifact staging and fail-closed secret scanning:

### Modified Files
- [`packages/brainsOS-appliance/packer/variables.pkr.hcl`](../packages/brainsOS-appliance/packer/variables.pkr.hcl):
  - Added `volume_throughput` (default `500` MB/s, up from AWS `gp3` baseline `125` MB/s), `volume_iops` (default `4000`, up from `3000`), `source_ami` (default `""`), and `incremental_build` (default `false`).
- [`packages/brainsOS-appliance/packer/brainsos-ami.pkr.hcl`](../packages/brainsOS-appliance/packer/brainsos-ami.pkr.hcl):
  - Parameterized `source_ami` vs dynamic `source_ami_filter` (Canonical Ubuntu 24.04 ARM64 when `source_ami == ""`).
  - Added builder `#cloud-config` `user_data` (`# BRAINSOS_PACKER_BUILD=true` + volatile `bootcmd` `systemctl mask --runtime brainsos-firstboot.service brainsos.service brainsos-system-api.service brainsos-resume.service` + `.brainsos-initialized` guard) so incremental builds atop older base AMIs (including `RC6` `ami-0eac84eb9a9415531`) never trigger `firstboot.sh` or boot 18 Docker containers during Packer provisioning, while leaving `/etc/systemd/system` units enabled on disk for the final snapshot.
  - Set `throughput = var.volume_throughput` (`500`) and `iops = var.volume_iops` (`4000`) on `/dev/sda1` `gp3` `launch_block_device_mappings`.
  - Updated Step 1 shell provisioner to quiesce inherited services/containers and clean `/opt/brainsos` while preserving `/opt/brainsos/.venv` for fast delta Python editable installs, and tagged AMIs with `BuildMode` (`incremental` vs `full`) and `BaseAMI`.
- [`packages/brainsOS-appliance/packer/provision.sh`](../packages/brainsOS-appliance/packer/provision.sh):
  - Added `--incremental` / `BRAINSOS_INCREMENTAL_BUILD` mode (`IS_INCREMENTAL_HOST=true` when `docker` and `node` are already installed on the base image): skips redundant full repository setup (`noble-proposed` bootstrap, NodeSource GPG/repo re-setup, Docker CE repo re-install) in favor of fast APT security delta updates, rebuilds only changed Docker layers (`make runner-base build` + `docker compose pull --ignore-buildable` + `docker image prune -f`), self-heals `.venv` if needed, cleans `.brainsos-wizard-completed` alongside `.brainsos-initialized` and `.env`, and runs the fail-closed `snapshot_scan`.
- [`packages/brainsOS-appliance/scripts/firstboot.sh`](../packages/brainsOS-appliance/scripts/firstboot.sh):
  - Added explicit `BRAINSOS_PACKER_BUILD=true` User Data early-exit guard.
- [`scripts/control/build-ami.sh`](../scripts/control/build-ami.sh):
  - Added `--incremental` (auto-discovers the newest `available` self-owned `brainsos-*` `arm64` AMI in `${AWS_REGION}`), `--from-ami <ami-id>` (explicit base AMI override with `^ami-[0-9a-f]{8,17}$` validation), `--volume-throughput <mbps>`, and `--volume-iops <iops>`.
  - Added wall-clock build timer (`completed in Xm Ys`) and build mode telemetry banner.
- [`packages/brainsOS-appliance/brainsos_appliance/builder.py`](../packages/brainsOS-appliance/brainsos_appliance/builder.py) & [`cli.py`](../packages/brainsOS-appliance/brainsos_appliance/cli.py):
  - Exposed `--from-ami` and `--incremental` in `brainsos-appliance build`.
- [`packages/brainsOS-appliance/README.md`](../packages/brainsOS-appliance/README.md) & [`README.md`](../README.md):
  - Documented fast incremental delta AMI builds alongside clean-room baseline builds.

### Created Files
- [`packages/brainsOS-appliance/tests/test_fast_ami_build.py`](../packages/brainsOS-appliance/tests/test_fast_ami_build.py):
  - 8 automated unit/integration tests covering Packer HCL invariants, `build-ami.sh --validate-only`, `--from-ami` dry-run variable injection, malformed AMI ID rejection, `--incremental` EC2 auto-discovery, Python CLI flag composition, `firstboot.sh` `BRAINSOS_PACKER_BUILD=true` bypass, and `provision.sh` incremental sanitization invariants.
