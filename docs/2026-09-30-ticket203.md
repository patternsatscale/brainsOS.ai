## 1. Summary of Changes

This ticket establishes the **Two-Repository Architecture** for brainsOS, decoupling proprietary agent intellectual property, OKF memories, custom personas, fleet manifests, and agent-authored codebases from the core open-source platform repository.

### Infrastructure & Orchestration
- **`.env.example` & `.env`**: Added `BRAINSOS_DATA_DIR` parameterization (default `./data` for local mode, or external path like `/Users/pats/Development/project_mJ` for decoupled mode). Commented out granular sub-directory overrides so all sub-paths default automatically to `${BRAINSOS_DATA_DIR}/<subfolder>`.
- **`docker-compose.yml`**: Parameterized all host-bind mounts for `./data` with `${BRAINSOS_DATA_DIR:-./data}` and individual directory overrides (`BRAINSOS_SETTINGS_DIR`, `BRAINSOS_SOULS_DIR`, `BRAINSOS_AGENT_MEMORIES_DIR`, `BRAINSOS_AGENT_WORKSPACES_DIR`, `BRAINSOS_AGENT_APPS_DIR`, `BRAINSOS_RUNNERS_DIR`, `BRAINSOS_CONTROL_PLANE_DIR`, `LITELLM_DB_DATA_DIR`).
- **`docker/langfuse/docker-compose.yml`**: Parameterized telemetry storage volumes with `${BRAINSOS_TELEMETRY_DIR:-...}`.
- **`config/templates/data-repo.gitignore`**: Created canonical `.gitignore` template for external private data repositories, ignoring volatile state (`.db`, `.sqlite`, `.pid`, `.sock`, telemetry blobs, mail spools) while versioning Markdown memories, souls, settings, and application canvases.
- **`config/caddy/Caddyfile`**: Resolved ambiguous duplicate site definition for `mail.local.brainsos.ai`, allowing Caddy reverse proxy to start cleanly and route `https://mail.local.brainsos.ai/SOGo` with TLS.
- **Core Repository `data/` Purged**: Purged untracked runtime state, databases, and proprietary personas from `brainsOS.ai/data/`, preserving only tracked `.gitkeep` files for clean open-source checkouts. All active IP and databases now reside exclusively in `/Users/pats/Development/project_mJ`.
