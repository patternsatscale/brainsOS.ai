## 1. Summary of Changes

### Configuration & Path Conventions
- **`.env.example`**:
  - Documented explicit storage path conventions:
    - **Default (Local macOS Dev & standard clone)**: Relative paths within project root (`./data/memories`, `./data/workspace`, `./data/litellm_db`).
    - **Production Appliance (ASUS Ascent GX10)**: Optional absolute paths for dedicated NVMe mounts (`/data/titan/memories`, `/data/titan/workspace`, `/data/titan/litellm_db`).
  - Added parameter `TITAN_WORKSPACE_DIR=./data/workspace`.
- **`.env`**: Configured `TITAN_WORKSPACE_DIR=./data/workspace`.
- **`.gitignore`**: Excluded `data/workspace/*` while whitelisting `!data/workspace/.gitkeep`.
- **`data/workspace/.gitkeep`**: Added placeholder to track the workspace directory structure in Git while keeping live runtime tools and credentials ignored.

### Container Topology & Infrastructure
- **`docker-compose.yml`**:
  - Updated Hermes service volume mount from Docker named volume (`hermes_runtime_state:/workspace`) to parameterized host bind-mount:
    ```yaml
    - ${TITAN_WORKSPACE_DIR:-./data/workspace}:/workspace
    ```
  - Removed obsolete named volume `hermes_runtime_state` from the root `volumes:` block.

### Automation, Backup & Verification Scripts
- **`scripts/setup-host.sh`**:
  - Added resolution for `TITAN_WORKSPACE_DIR` and scaffolding of target workspace directory (`1000:1000` UID/GID and `775` permissions on GX10/Linux; standard permissions on macOS).
  - Ensured `data/workspace/.gitkeep` presence.
- **`scripts/setup-hermes.sh`**:
  - Added idempotent scaffolding and permissions validation for `${WORKSPACE_DIR}` prior to building and launching the Hermes container.
- **`scripts/backup.sh`** *(NEW)*:
  - Full appliance data plane backup and restore manager.
  - Compresses all three data planes (`memories/`, `litellm_db/`, `workspace/`) into timestamped gzip archives: `data/backups/titan_data_YYYYMMDD_HHMMSS.tar.gz`.
  - Excludes recursive backups (`data/backups/`), volatile logs/pids (`data/control_plane/`), sockets, and OS artifacts (`.DS_Store`).
  - Embeds `manifest.json` with source paths, timestamps, and version metadata.
  - Implements restore verification (`--restore <archive>` with interactive or `-f/--force` bypass).
  - Implements archive inspection (`--list`).
  - Enforces automatic retention pruning (retains last 14 backups).
- **`scripts/verify-hermes.sh`** *(NEW)*:
  - Automated verification test suite validating:
    1. Unprivileged container health (UID 1000).
    2. Hermes web console accessibility (HTTP 200).
    3. Docker inspect verification that `/workspace` is a host `bind` mount.
    4. Bidirectional file write and host reflection test.
    5. Persistence across container recreation (`docker compose up -d --force-recreate hermes`).
    6. Skills auto-scaffolding (`/workspace/skills/hermes_okf.py`).
    7. Memory plane purity audit (Rule 1).
    8. Full data backup execution, archive integrity, and retention verification.
    9. Git secret hygiene check (`git ls-files` asserting no live workspace files are tracked).

### CI / CD & Architectural Documentation
- **`.github/workflows/pre-commit.yml`**:
  - Added CI step `Verify Agent Workspace Hygiene` to fail builds if any live runtime files in `data/workspace/` are tracked in Git.
- **`README.md`**:
  - Updated Section 1 ASCII architecture diagram to include `/data/titan/workspace (Agent State & Tools)`.
  - Documented unified host storage layout and cloud backup readiness (Google Drive / cloud sync targeting `/data/titan` on GX10 or `./data` locally).
  - Added `backup.sh` and `verify-hermes.sh` to the repository directory structure tree.

## 4. Architectural Boundaries & Cloud Sync Strategy

1. **Unified Storage Layout**:
   All state across the appliance is unified under a single host folder (`./data` in dev, `/data/titan` on GX10):
   ```text
   data/
   ├── memories/     (OKF markdown notes, rules, logs)
   ├── litellm_db/   (LiteLLM postgres dynamic database)
   └── workspace/    (Hermes tools, Signal credentials, Python packages, local databases)
   ```
2. **Cloud Backup (Google Drive / rclone / restic)**:
   On the ASUS GX10 (or local workstation), configuring Google Drive sync to target `/data/titan` (or `./data`) now protects 100% of the appliance's state without manual volume export scripts.
3. **Memory Plane Purity (Rule 1)**:
   The `/memories` mount remains 100% pure flat-file Markdown. All binary artifacts, Python virtual environments, Signal auth files, and local SQLite databases are strictly confined to `/workspace`.
