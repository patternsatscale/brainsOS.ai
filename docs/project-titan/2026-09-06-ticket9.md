## 1. Summary of Changes

### Dedicated Database Architecture & Dynamic Persistence
- [`docker-compose.yml`](file:///Users/pats/Development/project_titan/docker-compose.yml):
  - Renamed cluster to `name: titan` for consistent grouping in Docker CLI and UI.
  - Deployed `litellm-db` (`titan-litellm-db`, `postgres:16-alpine`) strictly bound to IPv4 loopback `127.0.0.1:${LITELLM_DB_PORT:-5432}:5432`.
  - Configured persistent host storage bind-mount `${LITELLM_DB_DATA_DIR:-./data/litellm_db}:/var/lib/postgresql/data`.
  - Placed the database on an isolated bridge network (`titan-litellm-net`).
- [`config/litellm/config.yaml`](file:///Users/pats/Development/project_titan/config/litellm/config.yaml):
  - Configured `general_settings.master_key: os.environ/LITELLM_MASTER_KEY` for proxy admin operations (`/model/new`, `/key/generate`, and UI).
  - Configured `general_settings.database_url: os.environ/DATABASE_URL` pointing to the dedicated PostgreSQL service.
  - Enabled `general_settings.store_model_in_db: true` to decouple dynamic runtime model definitions from static YAML.
- [`.env.example`](file:///Users/pats/Development/project_titan/.env.example):
  - Added templated configuration for `LITELLM_DB_DATA_DIR`, `LITELLM_DB_NAME`, `LITELLM_DB_USER`, `LITELLM_DB_PASSWORD`, `LITELLM_DB_PORT`, and `DATABASE_URL`.
- [`.gitignore`](file:///Users/pats/Development/project_titan/.gitignore):
  - Added `data/litellm_db/` and `data/postgres/` to ensure host database files are never committed to git.

### Host Automation & Provisioning Scripts
- [`scripts/setup-host.sh`](file:///Users/pats/Development/project_titan/scripts/setup-host.sh):
  - Added `prisma` package installation to virtualenv alongside `litellm[proxy]`.
  - Automated pre-generation of Prisma client bindings (`prisma generate --schema ...`).
  - Added pre-pull caching of `postgres:16-alpine`.
  - Added automated host storage scaffolding and permission management (`700`) for `LITELLM_DB_DATA_DIR`.
- [`scripts/start-control-plane.sh`](file:///Users/pats/Development/project_titan/scripts/start-control-plane.sh):
  - Exported virtualenv `bin` in `PATH` and exported `DATABASE_URL`.
  - Added automated pre-flight checks to verify PostgreSQL readiness, automatically launching `titan-litellm-db` via Docker Compose if not already active.
  - Added status reporting for the PostgreSQL database service.
  - Added idempotent auto-registration of the Hermes virtual key (`HERMES_LITELLM_KEY`) in PostgreSQL upon startup.
  - Hardened `stop_services` with graceful exit wait loops and port-listener fallbacks.

### Automated CI Isolation Guardrail
- [`.github/workflows/pre-commit.yml`](file:///Users/pats/Development/project_titan/.github/workflows/pre-commit.yml):
  - Added `Verify Control Plane Database Isolation & Guardrails` step validating that:
    1. Hermes container has zero database environment variables.
    2. `titan-litellm-db` shares no networks with Hermes (`titan-ingress` or `titan-internal`).
    3. `titan-litellm-db` is bound strictly to `127.0.0.1`.
    4. No database files exist in git tracking.

### Documentation Alignment

  - Added **Rule 6: Control Plane Database Isolation** codifying zero database visibility for Hermes and CI enforcement.

### 2. CI Database Isolation Check
```bash
$ bash -c "
HERMES_DB_ENV=\$(docker compose config | awk '/container_name: titan-hermes/,/container_name:/' | grep -iE 'POSTGRES|DATABASE_URL' || true)
if [ -n \"\${HERMES_DB_ENV}\" ]; then echo \"ERROR: \${HERMES_DB_ENV}\"; exit 1; fi

DB_NETWORKS=\$(docker compose config | awk '/container_name: titan-litellm-db/,/container_name:/' | grep -E 'titan-ingress|titan-internal' || true)
if [ -n \"\${DB_NETWORKS}\" ]; then echo \"ERROR: \${DB_NETWORKS}\"; exit 1; fi

DB_PORTS=\$(docker compose config | awk '/container_name: titan-litellm-db/,/container_name:/' | grep -E '0\.0\.0\.0.*5432|:[0-9]+:5432' || true)
if [ -n \"\${DB_PORTS}\" ]; then echo \"ERROR: \${DB_PORTS}\"; exit 1; fi

DB_FILES=\$(git ls-files | grep -E '(\.db$|\.sqlite|\.sql$|data/litellm_db/|data/postgres/)' || true)
if [ -n \"\${DB_FILES}\" ]; then echo \"ERROR: \${DB_FILES}\"; exit 1; fi

echo '✓ All isolation checks passed!'
"
# Output: ✓ All isolation checks passed!
```

### 4. Dynamic Model Registration & Chat Completion
```bash
# Register dynamic model
$ curl -s -X POST http://127.0.0.1:4000/model/new \
  -H "Authorization: Bearer ${LITELLM_MASTER_KEY}" \
  -H "Content-Type: application/json" \
  -d '{"model_name": "dynamic-gemma", "litellm_params": {"model": "ollama_chat/gemma2:2b", "api_base": "http://127.0.0.1:11434"}}'
# Output: {"model_id":"ece95225-8a4b-4b1d-8f96-dc63c8411963","model_name":"dynamic-gemma", ...}

# Restart control plane
$ ./scripts/start-control-plane.sh restart

# Query dynamic model via Hermes virtual key
$ curl -s -X POST http://127.0.0.1:4000/v1/chat/completions \
  -H "Authorization: Bearer ${HERMES_LITELLM_KEY}" \
  -H "Content-Type: application/json" \
  -d '{"model": "dynamic-gemma", "messages": [{"role": "user", "content": "Test persistence"}], "max_tokens": 10}'
# Output: {"id":"chatcmpl-97cf425b...","model":"dynamic-gemma","choices":[{"message":{"content":"Let's explore how to test for persistence.","role":"assistant"}}]}
```
