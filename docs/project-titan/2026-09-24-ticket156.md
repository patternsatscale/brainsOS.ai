# Ticket #156 Walkthrough: Deploy Lightweight Internal Email System with Shared Agent Mailboxes (SnappyMail)

## 1. Summary of Changes

This ticket delivers an asynchronous, human-auditable communication network linking autonomous agents (`operator`, `terrastella`, `bawtford`, `marvin`) and the human administrator (`admin@titan.local`) featuring the **Shared Mailbox Architecture**.

### A. Container Infrastructure & Mail Engine
- **[`docker/mail/Dockerfile`](file:///home/patternsatscale/ProjectTitan/docker/mail/Dockerfile)**: Ultra-lightweight native ARM64 image (51.8 MB total) combining Alpine Postfix (SMTP on ports 25 and 587) and Dovecot (IMAP on port 143, LMTP delivery, and Pigeonhole Sieve).
- **[`docker/mail/entrypoint.sh`](file:///home/patternsatscale/ProjectTitan/docker/mail/entrypoint.sh)**: Process supervisor managing daemon lifecycle, user seeding, Maildir directory scaffolding, and Dovecot ACL registrations.
- **[`docker/mail/dovecot/dovecot.conf`](file:///home/patternsatscale/ProjectTitan/docker/mail/dovecot/dovecot.conf)**: Dovecot configuration implementing local Maildir storage, authentication, Pigeonhole Sieve extension hooks, and the shared namespace `Agent Fleet/` with RFC 4314 IMAP ACL enforcement.
- **[`docker/mail/postfix/main.cf`](file:///home/patternsatscale/ProjectTitan/docker/mail/postfix/main.cf)** & **[`docker/mail/postfix/master.cf`](file:///home/patternsatscale/ProjectTitan/docker/mail/postfix/master.cf)**: Postfix configuration for trusted local network relay, Dovecot LMTP local transport, and Dovecot SASL authentication.
- **[`docker/mail/sieve/default.sieve`](file:///home/patternsatscale/ProjectTitan/docker/mail/sieve/default.sieve)**: Pigeonhole Sieve entry script with extension hook `/usr/lib/dovecot/sieve-pipe` ready for reactive webhook dispatch ([#164](https://github.com/patternsatscale/project-titan/issues/164)).

### B. Compose & Ingress Topology
- **[`docker-compose.yml`](file:///home/patternsatscale/ProjectTitan/docker-compose.yml)**: Added `mail-server` (`titan-net-mail-server`) and `snappymail` (`titan-net-snappymail`) services with parameterization, security options (`no-new-privileges:true`), and volume mappings strictly under `${TITAN_COMMS_DIR:-./data/comms}/email`.
- **[`config/caddy/Caddyfile`](file:///home/patternsatscale/ProjectTitan/config/caddy/Caddyfile)**: Added `(snappymail_backend)` reverse-proxy snippet and ingress virtual hosts for `http://mail.{$TITAN_DOMAIN:titan.local}`, `https://mail.{$TITAN_DOMAIN:titan.local}`, and `http://mail.localhost`.

### C. Provisioning & Verification Tooling
- **[`scripts/setup/setup-mail.sh`](file:///home/patternsatscale/ProjectTitan/scripts/setup/setup-mail.sh)**: Idempotent setup script scaffolding `./data/comms/email` directories, generating secure passwords, seeding `users`, `vmailbox`, and `virtual` tables, and pre-configuring SnappyMail domain configurations for zero-click login.
- **[`scripts/verify/verify-mail.sh`](file:///home/patternsatscale/ProjectTitan/scripts/verify/verify-mail.sh)**: 10-step automated verification suite validating container health, security profiles, memory consumption (< 100 MB), Caddy ingress, SMTP delivery, IMAP retrieval, shared folder ACLs, multi-tenant isolation, memory plane purity, and unit tests.

### D. Standalone Python Mail Client Package
- **[`packages/titan_mail/`](file:///home/patternsatscale/ProjectTitan/packages/titan_mail/)**: Zero-dependency standalone Python package (`TitanMailClient`) utilizing Python standard library (`smtplib`, `imaplib`, `email`) for RFC-compliant threading (`Message-ID`, `In-Reply-To`, `References`) and shared folder operations.
- **[`packages/titan_mail/tests/test_mail.py`](file:///home/patternsatscale/ProjectTitan/packages/titan_mail/tests/test_mail.py)**: Automated unit and integration test suite validating end-to-end roundtrip SMTP submission and IMAP reading.

### E. Configuration & Documentation
- **[`.env.example`](file:///home/patternsatscale/ProjectTitan/.env.example)**: Documented `MAIL_SMTP_PORT`, `MAIL_IMAP_PORT`, `SNAPPYMAIL_PORT`, and account password variables.
- **[`docker/mail/README.md`](file:///home/patternsatscale/ProjectTitan/docker/mail/README.md)**: Comprehensive architectural specification covering MTA/MDA components, memory budget (<100MB), shared namespace, RFC 4314 ACL model, storage topology under `/data/comms/email`, future VPN and Sieve webhook hooks, and operational CLI guide.
- **[`README.md`](file:///home/patternsatscale/ProjectTitan/README.md)**: Updated Appliance Service Directory table and repository scripts/packages tree.

## 4. Local Web Preview URLs & Verification Points

When running Project Titan:
- **SnappyMail Webmail (Localhost Ingress)**: [http://mail.localhost](http://mail.localhost)
- **SnappyMail Webmail (Appliance Ingress)**: [http://mail.titan.local](http://mail.titan.local)
- **SnappyMail Direct Container Port**: [http://localhost:8888](http://localhost:8888)

### Verification Instructions for Reviewer:
1. Open [http://mail.localhost](http://mail.localhost) in your browser.
2. Log in using the human administrator credentials:
   - **Email**: `admin@titan.local`
   - **Password**: `titan_admin_mail_secret_change_me` (or value of `ADMIN_MAIL_PASSWORD` in `.env`)
3. **Verify the Shared Folder Sidebar**:
   - Inspect the left folder sidebar: verify the `Agent Fleet` folder hierarchy is present with sub-folders for each active agent (`terrastella`, `bawtford`, `marvin`, `operator`).
   - Click on `Agent Fleet / terrastella` to view messages delivered to the agent.
4. **Verify Composition & Reply**:
   - Click **Compose** and send a test message to `bawtford@titan.local` or reply to an existing message. Verify delivery appears instantly in `Agent Fleet / bawtford`.
