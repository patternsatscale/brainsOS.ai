## 1. Executive Summary

Ticket #146 delivers a dedicated outbound **Tool Egress Gateway & Inspection Proxy** powered by **mitmproxy** (`mitmweb`) on `titan-internal`. This establishes real-time auditing, logging, and security observability over all outbound HTTP and HTTPS traffic initiated by autonomous agent tool executions (REST calls, web scraping, external search APIs, webhooks) while enforcing strict zero-leakage bypass policies (`NO_PROXY`) for local control plane inference (`host.docker.internal:4000`), messaging daemons (`signal-cli:8080`), and ingress services.

### Core Achievements
1. **Containerized Egress Inspection Proxy (`titan-tool-egress-proxy`)**:
   - Official `mitmproxy/mitmproxy:latest` service running natively on ARM64.
   - Forward proxy listening on `titan-internal:8082` (avoiding conflict with `signal-cli:8080`).
   - Web inspection console bound strictly to host loopback `127.0.0.1:8081` and accessible through Caddy at `http://efw.titan.local`, `http://firewall.titan.local`, and `http://efw.localhost`.
   - Protected by `TOOL_EGRESS_WEB_PASSWORD` with live flow inspection and event log streams.
2. **Automated Internal CA Trust Chain**:
   - Proxy CA certificate (`mitmproxy-ca-cert.pem`) persisted in named volume `tool_egress_proxy_data`.
   - Mounted read-only into all agent containers at `/etc/ssl/mitmproxy:ro`.
   - Automated startup boot hook `/etc/cont-init.d/01-tool-egress-ca` installs the certificate to `/usr/local/share/ca-certificates/mitmproxy-ca.crt` and updates the system trust store on boot.
   - Pre-configured environment variables (`REQUESTS_CA_BUNDLE`, `SSL_CERT_FILE`, `NODE_EXTRA_CA_CERTS`) ensure `curl`, OpenSSL, Python (`requests`, `httpx`, `urllib`), and Node.js runtimes trust intercepted HTTPS traffic cleanly without disabling TLS verification (`--insecure`).
3. **Declarative Fleet Egress & Strict Internal Bypass**:
   - Integrated into `config/agents.yaml` and compiled via `scripts/control/sync-agents.sh`.
   - Injects `HTTP_PROXY`, `HTTPS_PROXY`, `http_proxy`, `https_proxy`.
   - Injects strict `NO_PROXY` bypass for `localhost`, `127.0.0.1`, `host.docker.internal`, `proxy.local`, `litellm`, `signal-cli`, `titan-signal-cli`, `titan-litellm-db`, `*.titan.local`, and `*.titan.internal`.
   - LiteLLM inference, Signal messaging, and Caddy ingress bypass the tool proxy completely (preserving Rule 2 and Rule 10).
4. **Appliance Portal & Ingress Integration**:
   - Added reverse proxy route in Caddy for `efw.titan.local`, `firewall.titan.local`, and `efw.localhost`.
   - Added Egress Firewall card to Level 4 (Routing & Security Control Plane) on the Titan Appliance Portal (`http://titan.local` / `http://localhost`).
5. **Dedicated Automated Verification Suite**:
   - Created `scripts/verify/verify-tool-egress-proxy.sh` validating 7 critical assertion stages with 100% pass rate.

## 5. Local Web Preview URLs & Inspection Demo Guide

The egress firewall web dashboard is running live and accessible:

- **Egress Firewall Dashboard**:
  - Direct loopback: [http://localhost:8081/?token=titan_tool_egress_secret](http://localhost:8081/?token=titan_tool_egress_secret)
  - Clean local domain: [http://efw.titan.local/?token=titan_tool_egress_secret](http://efw.titan.local/?token=titan_tool_egress_secret)
  - Alternative alias: [http://firewall.titan.local/?token=titan_tool_egress_secret](http://firewall.titan.local/?token=titan_tool_egress_secret)
  - Chromium default: [http://efw.localhost/?token=titan_tool_egress_secret](http://efw.localhost/?token=titan_tool_egress_secret)
- **Appliance Control Center (Landing Page)**:
  - [http://titan.local](http://titan.local) / [http://localhost](http://localhost) (contains the new "Egress Firewall" card under Level 4).

### How to Demo & Inspect Live Outgoing Agent Traffic
1. Open [http://localhost:8081/?token=titan_tool_egress_secret](http://localhost:8081/?token=titan_tool_egress_secret) in your browser.
2. Click the **Flows** tab to observe live HTTP/HTTPS traffic.
3. Click the **Events** toggle or tab in the bottom bar to view live connection handshakes and server logs.
4. From your terminal, trigger an agent tool request:
   ```bash
   docker compose exec agent-terrastella curl -s https://httpbin.org/ip
   ```
5. Watch the flow appear instantly on the dashboard with full request/response inspectability.
