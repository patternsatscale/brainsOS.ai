### Architectural Guarantees:
1. **Hardware Concurrency & Memory Bus Protection (Rule 3)**:
   - On the ASUS Ascent GX10 appliance, heavy multi-step LLM reasoning saturates unified memory bandwidth. `packages/titan_queue` introduces a decoupled, reusable asynchronous work queue and `FIFOQueueWorker` enforcing strict concurrency (default `concurrency: 1`), exponential backoff retries, and dead-letter quarantine.
2. **Dual-Queue Architecture in `titan-mail`**:
   - **Queue A (`<agent_id>_fast_response`)**: Handles immediate acknowledgements and triage. When an inbound email arrives while the agent is busy, Queue A immediately returns a scripted status notification with RFC threading (`In-Reply-To`, `References`, `Re: <Subject>`) without blocking for hours.
   - **Queue B (`<agent_id>_workload`)**: Dequeues and serializes the full workload (`concurrency: 1`). When the hardware is ready, the agent executes the task, captures start/end timestamps, logs human-auditable execution reports to `/memories/logs/email_workload.md`, and serializes the event into RFC 5545 `.ics` format.
3. **SOGo Groupware & Native Calendar Alarms (Ticket #166)**:
   - Replaces SnappyMail with SOGo, unlocking CalDAV calendars, meeting invites, and automated email alarms via `/usr/sbin/sogo-ealarms-notify` (running on a 60-second cycle).
   - Natural trigger chain: SOGo Calendar Alarm -> Postfix (SMTP :25) -> Dovecot (LMTP :24) -> Pigeonhole Sieve Webhook -> Agent Wakes Up & Enqueues Workload!
4. **Control Plane Database Isolation (Rule 6)**:
   - SOGo persistence is hosted exclusively in `titan-sogo-db` (`postgres:16-alpine`), completely isolated from `titan-infra-litellm-db`.
   - Separate container, separate volume (`./data/comms/sogo/db`), separate network (`titan-internal` vs `titan-litellm-net`).
5. **Memory Plane Purity (Rule 1)**:
   - SQLite queue databases (`queue.db`), SOGo DB data, and calendar `.ics` files programmatically forbid storage paths within `/memories` or `agent_memories`.
   - Inbound email audits and workload execution summaries write exclusively in human-auditable Open Knowledge Format (OKF) Markdown to `/memories/logs/email_inbound.md` and `/memories/logs/email_workload.md`.
6. **Zero Manifest Drift (Rule 9)**:
   - Multi-tenant fleet manifest synchronization (`scripts/control/sync-agents.sh`) verified with zero drift.

## 2. Summary of Changes

### A. SOGo Groupware & Calendar Engine (`docker/sogo/` & Ticket #166)
- `docker/sogo/Dockerfile`: Native ARM64 container definition based on `debian:bookworm-slim`, packaging SOGo 5.8.0, local memcached, PostgreSQL client, procps, gosu, and `nginx-light`.
- `docker/sogo/nginx.conf`: In-container reverse proxy and static asset dispatcher. Directly maps and serves `/SOGo.woa/WebServerResources/` (CSS, JavaScript, Angular libraries, Material/Fira fonts, and themes) while proxying dynamic application and CalDAV requests to `sogod` on `127.0.0.1:20001`.
- `docker/sogo/sogo.conf`: Main SOGo configuration enabling:
  - Internal loopback listening on `127.0.0.1:20001` behind Nginx.
  - Database URLs pointing to `titan-sogo-db` (`sogo_user_profile`, `sogo_folder_info`, `sogo_sessions_folder`, `sogo_admin`, `sogo_alarms_folder`).
  - `SOGoEnableEMailAlarms = YES;` and `OCSEMailAlarmsFolderURL` for calendar alarms.
  - SQL User authentication source querying `sogo_users` with plain passwords.
  - SMTP/IMAP integration with `mail-server`.
- `docker/sogo/entrypoint.sh`: Wait for `titan-sogo-db`, seed `sogo_users` schema and fleet accounts (supporting both short username and email login), start local memcached, spawn background `sogo-ealarms-notify` 60s daemon, start Nginx on port 20000, and exec `sogod` with `-WONoDetach YES` on 127.0.0.1:20001.
- `docker-compose.yml`: Replaced `snappymail` with `sogo-db` (isolated PostgreSQL 16 on port 5434) and `sogo` (port 20000).
- `config/caddy/Caddyfile`: Updated `(sogo_backend)` reverse proxying `sogo:20000` with redirect `/ -> /SOGo` for `mail.localhost` and `mail.titan.local`.
- `scripts/setup/setup-sogo.sh`: Automated scaffolding, build, service launch, and readiness verification.
- `scripts/verify/verify-sogo.sh`: Comprehensive verification suite testing container status, unprivileged execution (Rule 4), DB isolation (Rule 6), HTTP routing, direct and Caddy static asset resolution (`styles.css`, `Common.js`), SQL user seeding, `sogo-ealarms-notify` binary execution, memory plane purity (Rule 1), and footprint benchmark (Rule 3).

### B. Modular Asynchronous Work Queue (`packages/titan_queue/` & Ticket #168)
- `packages/titan_queue/pyproject.toml`: Standalone Python package definition.
- `packages/titan_queue/README.md`: Architecture guide, usage examples, and queue semantics.
- `packages/titan_queue/titan_queue/models.py`: `Task` model, `TaskStatus` lifecycle states (`QUEUED`, `PROCESSING`, `COMPLETED`, `FAILED`, `DEAD_LETTER`), timestamps, retries, and error tracking.
- `packages/titan_queue/titan_queue/queue.py`: `WorkQueue` abstraction supporting named queues, item enqueueing, dequeueing, status inspection, and registry management (`get_queue`).
- `packages/titan_queue/titan_queue/worker.py`: `FIFOQueueWorker` enforcing strict concurrency serialization (default `concurrency=1`), backoff retries, and graceful drain.
- `packages/titan_queue/titan_queue/backends/base.py`: Abstract `QueueBackend` interface.
- `packages/titan_queue/titan_queue/backends/memory.py`: Event-driven in-memory backend (0 polling overhead).
- `packages/titan_queue/titan_queue/backends/sqlite.py`: Crash-resilient SQLite backend with WAL mode and programmatic Rule 1 purity enforcement.
- `packages/titan_queue/tests/`: 13 pytest unit tests validating FIFO ordering, concurrency limits, retries, dead-lettering, and Rule 1 purity violation guards.

### C. Calendar / ICS Subsystem (`packages/titan_mail/`)
- `packages/titan_mail/titan_mail/calendar.py`: Pure-Python RFC 5545 generator (`generate_ics_event`, `write_ics_file`) with UID correlation, duration calculation, and Rule 1 path validation.
- `packages/titan_mail/titan_mail/__init__.py`: Exported calendar helpers alongside `TitanMailClient`.
- `packages/titan_mail/tests/test_calendar.py`: Unit tests verifying RFC 5545 compliance, character escaping, datetime formatting, and Rule 1 exception enforcement.

### D. Hermes Agent Runtime & Mail Plugin (`docker/hermes/`)
- `docker/hermes/Dockerfile`: Added copy and `uv pip install -e` for `packages/titan_queue`.
- `docker/hermes/plugins/titan-mail/__init__.py`:
  - Integrated `titan_queue` dual queues (`<agent>_fast_response` and `<agent>_workload`).
  - Implemented `_handle_fast_response_task`: audits inbound mail to `/memories/logs/email_inbound.md`, detects active workload state, and returns fast scripted acknowledgement with RFC threading.
  - Implemented `_handle_workload_task`: serializes execution with `concurrency: 1`, generates RFC 5545 `.ics` file in `/workspace/calendar/`, and writes execution log to `/memories/logs/email_workload.md`.
  - Updated `_handle_agent_email_webhook`: pushes inbound emails to both queues and returns `HTTP 200 OK` with task correlation IDs immediately without blocking Dovecot LMTP.

### E. Mail Server Subsystem (`docker/mail/`)
- `docker/mail/dovecot/dovecot.conf`: Added `import_environment` passing API keys and ports to Dovecot child processes.
- `docker/mail/entrypoint.sh`: Exported environment variables to `/etc/environment` for Sieve pipe subprocesses.
- `docker/mail/agent-webhook.sh`: Sourced `/etc/environment` if available to ensure reliable API key authentication under Dovecot `vmail` user.
- `docker/mail/README.md`: Updated architecture documentation to reflect SOGo replacement and calendar integration.

### F. Global Configuration & Documentation Alignment
