## 1. Executive Summary

Ticket #157 completes the systematic consolidation of Project Titan's persistent data taxonomy under `./data/`. Following the initial partitioning of agent memories and sandboxes, this ticket organizes the remaining scattered directories (`litellm_db`, `langfuse_db`, `langfuse_clickhouse`, `langfuse_minio`, `langfuse_redis`) into clean, functional architectural domains.

The resulting top-level storage taxonomy under `data/` contains exactly six disciplined domains:
```text
data/
├── agent_memories/      # L5: Pure human-auditable OKF Markdown per agent
├── agent_workspaces/    # L5: Execution sandboxes, pip packages, local SQLite DBs per agent
├── backups/             # System-wide compressed archives and snapshots
├── comms/               # L7: Communications daemons (Signal session store, future Email)
├── control_plane/       # L4: Control plane state (LiteLLM Postgres DB, pids, logs, caddy root CA)
└── telemetry/           # L4/L5: Langfuse v4 observability stack (ClickHouse, Postgres, MinIO, Redis)
```

### Key Accomplishments
1. **Zero Data Loss Migration for LiteLLM Control Plane**:
   - Preserved the authentic, production LiteLLM PostgreSQL database (created Sep 8 with dynamic virtual keys and 78 tables) from `data/litellm_db` into `data/control_plane/litellm_db`.
   - Handled non-root host permission boundaries safely using ephemeral Alpine container preservation (`UID 70`, `mode 700`).
   - Verified virtual keys and agent registration persist seamlessly.
2. **Langfuse Telemetry Stack Consolidation**:
   - Grouped all four persistent stores of the Langfuse v4 observability engine into `data/telemetry/`:
     - `data/langfuse_clickhouse` -> `data/telemetry/clickhouse/`
     - `data/langfuse_db` -> `data/telemetry/postgres/`
     - `data/langfuse_minio` -> `data/telemetry/minio/`
     - `data/langfuse_redis` -> `data/telemetry/redis/`
   - Updated `docker/langfuse/docker-compose.yml`, `docker/langfuse/.env`, `docker/langfuse/.env.example`, and `scripts/setup/setup-langfuse.sh`.
   - Re-launched all 4 storage containers and verified `healthy` status.
3. **Automated Fleet Synchronization & Memory Indexing**:
   - Updated `scripts/control/sync-agents.sh` to write the SilverBullet / PKM navigation index to `data/agent_memories/index.md` instead of creating an obsolete `data/memories/` folder.
   - Verified zero fleet drift across both `config/agents.yaml` and `config/agents.local.yaml`.
4. **Backup Utility Alignment**:
   - Updated `scripts/control/backup.sh` to target `data/control_plane/litellm_db` by default (with backward-compatible fallback to `data/litellm_db`).
   - Verified that full backup creates archives containing `./litellm_db`, `./comms`, `./workspace`, and enforces the 14-archive retention policy.
5. **CI/CD Hygiene & Editor Excludes**:
   - Updated `.gitignore` to track `.gitkeep` while ignoring live state in `data/control_plane/*` and `data/telemetry/*`.
   - Updated `.github/workflows/pre-commit.yml` to assert zero git tracking of live database and telemetry files.
   - Updated VS Code / Operator IDE `files.watcherExclude` and search exclusions in `config/editor/settings.json`, `config/editor/titan.code-workspace`, and `docker/editor/entrypoint.sh` to prevent inotify exhaustion.
6. **Documentation & Spec Alignment**:
   - Updated `README.md` and `AGENTS.md` (Rule 9 and Portability Rules) to codify the new storage taxonomy and parameterization defaults.
