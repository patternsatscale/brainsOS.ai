## 5. Architectural Clarifications & Technical Notes

### What Does the "120 Orphans" Log in code-server Mean?
In the code-server extension host logs, the Foam PKM extension (`foam.foam-vscode`) activates on the view `onView:foam-vscode.orphans`. In personal knowledge management (PKM) and Zettelkasten terminology, an **"orphan note"** is simply a markdown note that has zero incoming wiki-links (`[[note]]`) from other notes in the knowledge graph. 

Because `/data/agent_memories` contains ~120 markdown files generated by agents that do not use foam wiki-link syntax, Foam classifies them as standalone/orphan notes in its graph view. It is purely an informational PKM graph metric—it has zero relationship to orphaned OS processes, zombie containers, or filesystem leaks.

### Parameterized Inference Engine Routing (`BRAINSOS_CORE_MODEL`)
Rather than hardcoding `qwen3.8:latest` in `config/litellm/config.yaml`, the default `brainsos-core` model alias is now parameterized using LiteLLM's native `os.environ/BRAINSOS_CORE_MODEL` syntax. This allows macOS developers running local, memory-constrained models like `gemma2:2b` or custom Ollama tags to configure their inference model directly via `.env` without modifying repository configuration templates.

## 6. Post-Session Addendum: Tool-Calling Fix (`brainsos-core` → `llama3.2:3b`)

**Issue**: After the LiteLLM Connector extension was connected and the `"secret": true` patch was applied, VS Code Copilot Chat successfully reached LiteLLM but returned:
```
LiteLLM Error (litellm:4000/brainsos-core): litellm.BadRequestError: Ollama_chatException - 
{"error":"registry.ollama.ai/library/gemma2:2b does not support tools"}
```

**Root Cause**: Copilot Chat agent mode unconditionally includes a `tools` array in every completion request. `gemma2:2b`, the only model installed in Ollama, does not implement the OpenAI function-calling interface and rejects such requests.

**Fix Applied**:
1. **Pulled `llama3.2:3b`** (2GB, supports tool-calling natively):
   ```bash
   ollama pull llama3.2:3b  # → success
   ```
2. **Updated `BRAINSOS_CORE_MODEL`** in `.env`, `.env.example`, and `start-control-plane.sh` default fallback from `ollama_chat/gemma2:2b` → `ollama_chat/llama3.2:3b`.
3. **Restarted control plane** (`./scripts/control/start-control-plane.sh stop && start`).
4. **Codified the `"secret": true` Dockerfile patch** in `docker/editor/Dockerfile` (post-extension-install `RUN` step using `python3` string replace). This makes every fresh container build automatically apply the patch, eliminating the manual ad-hoc patching step inside the running container.
