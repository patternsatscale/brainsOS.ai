## 1. Executive Summary & Architectural Alignment

Ticket #261 modularized the monolithic `docker-compose.yml` into a declarative 5-plane Compose v2 structure located under `docker/compose/` using Docker Compose v2's native `include:` directive. 

Rather than adopting an abstract 5-tier OS model, the architecture was intentionally aligned with **Option A**: the **brainsOS Plane Architecture** (`brainsos-<plane>-<service>`). This creates a direct, intuitive 1:1 blueprint for the future AWS cloud migration ([#251](https://github.com/patternsatscale/brainsOS.ai/issues/251)):

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. Ingress Plane        docker/compose/compose.ingress.yml                  │
│    - brainsos-ingress-caddy (Port 80/443, Route 53 / Internal CA)           │
├─────────────────────────────────────────────────────────────────────────────┤
│ 2. Agent Plane          docker/compose/compose.agents.yml                   │
│    - brainsos-agent-runner-hermes (:8642)                                   │
│    - brainsos-agent-runner-openai (:8002)                                   │
│    - brainsos-agent-egress-proxy (:8081/8082 with in-transit token injection)│
│    - brainsos-agent-mail-ingress (sieve mail receiver)                      │
├─────────────────────────────────────────────────────────────────────────────┤
│ 3. Control Plane        docker/compose/compose.control.yml                  │
│    - brainsos-control-litellm (:4000 gateway)                               │
│    - brainsos-control-litellm-db (PostgreSQL, isolated Rule 6)              │
├─────────────────────────────────────────────────────────────────────────────┤
│ 4. Application Plane    docker/compose/compose.apps.yml                     │
│    - brainsos-app-code-server (:8443)                                       │
│    - brainsos-app-sogo & brainsos-app-sogo-db (:20000)                      │
│    - brainsos-app-mail-server (SMTP/IMAP)                                   │
│    - brainsos-app-signal-cli (:8080)                                        │
│    - brainsos-app-auth-server, worker, redis, db (Authentik IdP & SSO)      │
├─────────────────────────────────────────────────────────────────────────────┤
│ 5. Telemetry Plane      docker/compose/compose.telemetry.yml                │
│    - brainsos-telemetry-langfuse-web (:3001)                                │
│    - brainsos-telemetry-langfuse-worker                                     │
│    - brainsos-telemetry-clickhouse (:8123/:9000)                            │
│    - brainsos-telemetry-redis (:6379)                                       │
│    - brainsos-telemetry-minio (:9000/:9001)                                 │
│    - brainsos-telemetry-db (PostgreSQL)                                     │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Inviolable Invariant Maintained: Zero Internal DNS Disruption
All internal Docker network aliases (`litellm`, `litellm-db`, `caddy`, `mail-server`, `runner-hermes`, `runner-openai`, `sogo`, `authentik-server`, `egress-proxy`, etc.) were strictly retained across all planes. Consequently, internal inter-container communication, Caddy upstreams, and environment parameters experienced zero service interruption.
