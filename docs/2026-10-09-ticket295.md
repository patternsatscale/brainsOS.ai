# Ticket #295 Walkthrough: Async Email → Hermes /v1/runs Dispatch with Result & Failure Replies (Concurrency = 1)

## Summary of Changes

This ticket resolves the foundational concurrency, timeout, and tracing issues in brainsOS email-triggered agent execution:
1. **Asynchronous Run Dispatch**: Replaced blocking `POST /v1/chat/completions` (which timed out after 180s and left orphaned agent loops thrashing LiteLLM with HTTP 429 rate limit errors) with asynchronous `POST /v1/runs` and non-blocking `GET /v1/runs/{id}` polling.
2. **Hardware Serialization (Rule 3)**: Enforced strict single-concurrency at both the Hermes layer (`gateway.api_server.max_concurrent_runs: 1`) and the LiteLLM gateway (`max_parallel_requests: 1`), backed by worker exponential backoff.
3. **Queue Checkpointing & Long-Running Heartbeats**: Added worker lease heartbeats and task payload persistence in `brainsos-queue` so multi-hour runs are never reclaimed prematurely by the queue, and worker restarts resume polling existing runs via `hermes_run_id` without resubmitting duplicate runs.
4. **Clean Failure Replies & OKF Hygiene**: On failure, cancellation, interruption, or wall-clock budget exhaustion (`HERMES_RUN_MAX_SEC`), senders receive a polite, human-friendly failure email with actionable recommendations; raw tracebacks and infrastructure errors are never sent to users and never written to OKF memory.
5. **Unified Langfuse Sessions**: Implemented canonical thread session keys (`mail-<agent>-<thread>`) shared by Hermes turn traces, LiteLLM generation traces (via `brainsos-litellm-session` Hermes plugin), and host-level `email-run` ingestion traces.
6. **Zero-Loss Spool & Ingress Hygiene**: Fixed race conditions in `docker/mail/agent-webhook.sh` using atomic `mktemp` to prevent sub-second filename collisions, and added graceful permission fallbacks for spool `.done` markers.
7. **Email Chain Preservation (Inbound & Outbound)**:
   - Fixed inbound email body parsing in `brainsos_mail/parser.py`: `clean_email_body` now preserves the email chain by default (`strip_chain=False`), only stripping trailing signature noise, so agents receive the complete, useful context of forwarded or replied threads.
   - Populated `body`, `html_body`, and `date` in `ParsedInboundEmail`.
   - In outbound replies, `compose_reply_body` quotes the previous email chain below the agent's response in both plain text (`> ...`) and HTML (`<blockquote class="brainsos-quote">...</blockquote>`), preserving the complete conversational trail in mail clients.
8. **HTML vs Markdown Email Responses**:
   - Instructed the agent in `HermesMailAdapter` system prompt to format email responses directly in clean, modern HTML rather than Markdown (using `<p>`, `<strong>`, `<em>`, `<ul>`, `<li>`, `<code>`, `<pre>`, `<blockquote>`, `<h3>`, `<a>`).
   - Implemented `markdown_to_clean_html` and `html_to_plain_text` normalizers in `brainsos_agent/mail_runs.py` to ensure emails are always formatted as rich HTML with a clean plain-text fallback.
   - Added `html_body` support to `OutboundEmail` and `BrainsOSMailClient.send_mail`, sending proper RFC-standard `multipart/alternative` MIME messages.
9. **HTML Pre-Check Before Markdown Conversion**:
   - Implemented `is_valid_html(text: str) -> bool` and `_HTMLValidator` in `brainsos_agent/mail_runs.py` using Python's standard `html.parser.HTMLParser`.
   - Validates whether an agent's response payload is already well-formed HTML (full documents or fragments) before attempting any Markdown conversion.
   - Distinguishes genuine HTML from plain text, mathematical inequalities (`5 < 10`), and angle-bracketed email addresses (`<user@domain>`).
   - Full HTML documents (`<!DOCTYPE html>`, `<html>`, `<body>`) are preserved untouched without wrapping in extraneous container tags.
   - Quoted email chains in `compose_reply_body` are inserted before `</body>` when full HTML documents are used.
10. **Email Reply Hygiene & Preamble/Verifier Stripping**:
   - Implemented `sanitize_agent_reply` in `brainsos_agent/mail_runs.py` to defensively strip leading conversational chatter before salutations (`Dear`, `Hello`, `Hi`) and remove trailing runtime diagnostic footers (`File-mutation verifier:`, `Turn completion explainer:`).
   - Tightened `_assemble_system_prompt_with_working_memory` in `HermesAdapter` instructing agents to start email responses immediately with the greeting without preliminary meta-commentary.
   - Configured `HERMES_WRITE_SAFE_ROOT=/opt/data:/tmp:/data`, `HERMES_FILE_MUTATION_VERIFIER=false`, and `HERMES_TURN_COMPLETION_EXPLAINER=false` in `compose.agents.yml` and `config.yaml`.
11. **Telemetry Hygiene & Langfuse Tracing Optimization**:
   - Disabled Hermes OTLP gateway health check exports (`gateway_health_export.enabled: false`) to eliminate empty 0-second traces from flooding the Langfuse UI.
   - Omitted `metadata.session_id` from the upstream LiteLLM provider plugin (`brainsos-litellm-session`) so individual LLM calls do not fragment the Langfuse session view with disconnected root traces.

## Acceptance Criteria Verification

- [x] **`HermesMailAdapter` dispatches via `POST /v1/runs` with instructions, conversation history, input, session_id, and model (no `/v1/chat/completions`)**: Verified in `brainsos_agent/adapters/hermes.py` and unit tests.
- [x] **Worker polls `GET /v1/runs/{run_id}` until terminal status with configurable wall-clock budget (`HERMES_RUN_MAX_SEC`) and `/stop` interruption**: Verified in `HermesMailAdapter.execute_run()` and unit tests.
- [x] **`run_id` is stored on the queue task; worker resumes polling existing run after restart; retried submits do not duplicate runs**: Verified in `brainsos_agent/worker.py` and `test_worker_runs.py`.
- [x] **`completed`: Assistant turn recorded in OKF and exactly ONE reply email sent (no acknowledgement email)**: Verified in `verify-email-runs.sh` (1 reply received, 0 duplicates in grace window).
- [x] **`failed` / `cancelled` / `interrupted` / budget exceeded: Failure email sent with plain explanation and recommendations; raw errors never sent to user or OKF**: Verified in `mail_runs.failure_email_body()` and `test_hermes_adapter.py`.
- [x] **Concurrency = 1 enforced at both layers**:
  - LiteLLM `max_parallel_requests: 1` active in control plane.
  - Hermes `gateway.api_server.max_concurrent_runs: 1` configured in `config.yaml` and applied to live runner.
  - Worker backs off on Hermes `429 Too many concurrent runs`.
- [x] **OKF is single source of history (Hermes `state.db` not relied on)**: Clean history passed into `/v1/runs` instructions and turns written directly to `/memories`.
- [x] **Spool hygiene: `.done` written on `DEAD_LETTER` and success; worker restart does not replay already-queued or finished emails**: Verified in `worker.py` spool scanner.
- [x] **Langfuse unified session**:
  - Canonical session key `mail-<agent>-<thread>` used across Hermes, LiteLLM, and queue worker traces.
  - Hermes traces carry agent identity and sender (`user_id`).
  - Failed runs produce error-level trace.
  - Both Hermes plugin and LiteLLM callback enabled.
- [x] **Unit tests cover adapter submit/poll/terminal states, failure generation, and HTML conversion/validation**: 129 tests passing across all three packages.
- [x] **Email chain preservation**: Verified inbound threads are not truncated and outbound replies quote prior turns in both HTML and plain text.
- [x] **HTML email responses**: Agent instructed to output HTML, and replies are dispatched as RFC-compliant `multipart/alternative` with HTML styling.
- [x] **HTML Pre-Check before Markdown Conversion**: Verified `is_valid_html` checks and preserves pre-existing or user-requested HTML payloads directly without Markdown conversion.
- [x] **End-to-end check**: Verified via `./scripts/verify/verify-email-runs.sh --agent bawtford` (`has_html=True`, `has_chain=True`).
