## 1. Summary of Changes

### OKF Scaffolding & Starter Templates
- [`config/memories/index.md`](file:///Users/pats/Development/project_titan/config/memories/index.md): Dedicated SilverBullet homepage for Project Titan featuring quick navigation to memory zones (`knowledge/`, `rules/`, `logs/`), active rules queries, recent knowledge queries, and operator instructions.
- [`config/memories/knowledge/README.md`](file:///Users/pats/Development/project_titan/config/memories/knowledge/README.md) & [`template.md`](file:///Users/pats/Development/project_titan/config/memories/knowledge/template.md): Knowledge base specification and reusable OKF note template with YAML frontmatter.
- [`config/memories/knowledge/working_memory.md`](file:///Users/pats/Development/project_titan/config/memories/knowledge/working_memory.md): Agent working memory and active task scratchpad.
- [`config/memories/rules/README.md`](file:///Users/pats/Development/project_titan/config/memories/rules/README.md), [`template.md`](file:///Users/pats/Development/project_titan/config/memories/rules/template.md), & [`memory_purity_guardrail.md`](file:///Users/pats/Development/project_titan/config/memories/rules/memory_purity_guardrail.md): Operator guardrails and behavioral rule templates, plus starter memory purity rule.
- [`config/memories/logs/README.md`](file:///Users/pats/Development/project_titan/config/memories/logs/README.md) & [`template.md`](file:///Users/pats/Development/project_titan/config/memories/logs/template.md): Audit log specifications and run summary template.

### Hermes OKF Plugin & Agent Runtime Integration
- [`docker/hermes/hermes_okf.py`](file:///Users/pats/Development/project_titan/docker/hermes/hermes_okf.py): Standalone Python module and CLI tool implementing the `hermes-okf` plugin:
  - Parses and serializes OKF Markdown with YAML frontmatter without external pip dependencies.
  - Dynamically synthesizes active rules from `/memories/rules/` and working memory into agent reasoning prompts based on active `INFERENCE_NUM_CTX` budget.
  - Provides full-text keyword search and category browsing across notes.
  - Enforces strict memory purity by blocking binary files, SQLite databases, and package caches.
  - Functions both as an importable library and as a standalone sandbox CLI tool (`/workspace/skills/hermes_okf.py`).
- [`docker/hermes/server.py`](file:///Users/pats/Development/project_titan/docker/hermes/server.py):
  - Injects active rules and working memory into LiteLLM completions prompt context (`/api/chat`).
  - Added `/api/memories/note` (read note), `/api/memories/search` (full-text search), `/api/memories/purity` (purity audit), and upgraded `/api/memories` list handler.
  - Added automatic installation of `hermes_okf.py` into `/workspace/skills` on startup.
  - Enhanced dashboard with an interactive OKF Memory Explorer featuring category filtering, note viewer, and direct link to SilverBullet.
- [`docker/hermes/Dockerfile`](file:///Users/pats/Development/project_titan/docker/hermes/Dockerfile): Bundles `hermes_okf.py` into `/app` and `/workspace/skills`.
- [`config/hermes/config.json`](file:///Users/pats/Development/project_titan/config/hermes/config.json): Added `hermes-okf` plugin configuration and context window parameters.

### Control Plane & Hardware-Adaptive Context Scaling
- [`config/litellm/config.yaml`](file:///Users/pats/Development/project_titan/config/litellm/config.yaml): Added `num_ctx: os.environ/INFERENCE_NUM_CTX` to Ollama models.
- [`.env.example`](file:///Users/pats/Development/project_titan/.env.example) & [`.env`](file:///Users/pats/Development/project_titan/.env): Configured `INFERENCE_NUM_CTX=4096` safe default for 16GB macOS workstations.
- [`scripts/setup-host.sh`](file:///Users/pats/Development/project_titan/scripts/setup-host.sh): Added hardware detection logic that scales `INFERENCE_NUM_CTX=32768` on ASUS GX10 / DGX OS while keeping `4096` on macOS.
- [`scripts/start-control-plane.sh`](file:///Users/pats/Development/project_titan/scripts/start-control-plane.sh): Exports `INFERENCE_NUM_CTX` to the LiteLLM process environment.

### Docker Topology & Service Hardening
- [`docker-compose.yml`](file:///Users/pats/Development/project_titan/docker-compose.yml):
  - Hardened `silverbullet` service with unprivileged execution `user: "${PUID:-1000}:${PGID:-1000}"` and `security_opt: ["no-new-privileges:true"]`.
  - Maintained isolated network attachment strictly to `titan-ingress`.
  - Passed `INFERENCE_NUM_CTX` to `hermes` container.
- [`.gitignore`](file:///Users/pats/Development/project_titan/.gitignore): Preserved subfolder `.gitkeep` markers and ensured memory logs (`!data/memories/logs/**`) remain tracked for human auditability.

### Automation Scripts & Documentation
- [`scripts/setup-memories.sh`](file:///Users/pats/Development/project_titan/scripts/setup-memories.sh): Automated, idempotent script that scaffolds OKF directories, seeds templates, enforces uniform permissions (`1000:1000`), pulls native ARM64 image, and validates purity.
- [`scripts/verify-memories.sh`](file:///Users/pats/Development/project_titan/scripts/verify-memories.sh): Comprehensive automated verification suite testing SilverBullet availability, bi-directional sync, rule injection, purity, and security boundaries without ad-hoc manual docker commands.
- [`README.md`](file:///Users/pats/Development/project_titan/README.md): Documented Phase 3 completion, memory plane layout, and added Phase 5 to the architectural roadmap.
- **GitHub Issue #19**: Spun out [[Phase 5] Benchmarking and Optimization: Inference Engine Evaluation (Ollama vs vLLM/SGLang), Context Scaling & Observability (Langfuse)](https://github.com/patternsatscale/project-titan/issues/19) into the project backlog.
