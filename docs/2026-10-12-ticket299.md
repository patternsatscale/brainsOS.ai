# Ticket #299 Walkthrough: Unified Langfuse Thread Trace, OTLP Migration & Gateway Health Cleanup

## Summary of Changes

This ticket resolves root causes behind fragmented Langfuse session views, duplicate LLM traces, broken timeline rendering, empty `hermes.gateway_health` traces, and the *"Custom instrumentation / ingestion-api-dual-write"* warning in Langfuse v4:

1. **Unified Thread Trace Architecture & brainsOS Event Naming**:
   - Instead of emitting disconnected root traces with random UUIDs for each email run, the queue worker now derives the exact deterministic trace ID that Hermes uses for `/v1/runs` sessions: `thread_trace_id(session_id) = sha256(f"{sid}::{sid}")[:16]`.
   - The worker emits exactly **one** `email-run <agent_id>` span per email directly onto that thread trace via native OTLP v4 (`/api/public/otel/v1/traces`) with `x-langfuse-ingestion-version: 4`. The span includes `langfuse.trace.name` (`brainsos: email: <Subject>` or `brainsos: email: <agent_id>`), `langfuse.trace.tags`, `user.id` = sender, `session.id` = thread session, exact run duration, and `ERROR` status message on failure.
   - Hermes' `observability/langfuse` plugin (`docker/hermes/plugins/observability/langfuse/__init__.py`) is patched and mounted into the Hermes runner. For `mail-*` sessions, it sets `effective_trace_name = f"brainsos: email: {agent_id}"` and names the root observation `effective_trace_name` rather than hardcoding `"Hermes turn"`.
   - The full email run sequence renders on a single, continuous, chronological timeline in Langfuse without duplicates or scattered trace fragments.

2. **Pure OTLP v4 Migration (Eliminating Legacy Ingestion Warning)**:
   - Migrated worker-side tracing in `packages/brainsOS-agent/brainsos_agent/langfuse_trace.py` exclusively to `/api/public/otel/v1/traces` with `x-langfuse-ingestion-version: 4`. Zero calls to `/api/public/ingestion` or `POST /api/public/traces` exist in production code.
   - Configured `OTEL_EXPORTER_OTLP_HEADERS=x-langfuse-ingestion-version=4` and `OTEL_EXPORTER_OTLP_TRACES_HEADERS=x-langfuse-ingestion-version=4` on LiteLLM in `docker/compose/compose.control.yml`.
   - Migrated the probe in `scripts/verify/verify-langfuse.sh` from `/api/public/ingestion` to `/api/public/otel/v1/traces`.
   - Removed spoofed SDK headers (`X-Langfuse-Sdk-Name: python`) that previously failed to satisfy Langfuse v4's ingestion analyzer.

3. **LiteLLM Deduplication & IDE Tracing Preservation**:
   - Updated the Hermes provider plugin `docker/hermes/plugins/model-providers/brainsos-litellm-session/__init__.py` to inject `"no-log": True` into the extra body of all Hermes-originated completion requests. This instructs LiteLLM to bypass non-proxy logging callbacks (since Hermes already traces its own LLM calls) while keeping proxy cost and spend tracking active.
   - Switched LiteLLM's global callbacks in `config/litellm/config.yaml` from legacy `langfuse` + bare `otel` to native `langfuse_otel`. Direct API calls, scripts, and operator IDE completions (`code-server` / Cline / Continue) remain fully traced by LiteLLM without generating duplicate traces for Hermes turns.

4. **Hermes Gateway Health Cleanup**:
   - Extended `scripts/setup/apply-hermes-guards.sh` to idempotently enforce `monitoring.gateway_health_export.enabled: false` and `monitoring.export.otlp.enabled: false` on the live runner configuration (`data/runners/hermes/config.yaml`), eliminating empty 0-second `hermes.gateway_health` traces that flooded existing hosts due to `bootstrap-env.sh` copying runner templates with `cp -n`.

5. **Real-Time OTLP Processing**:
   - Configured `LANGFUSE_MIGRATION_V4_NATIVE_OTEL_BEHAVIOUR=direct` on `langfuse-web` and `langfuse-worker` in `docker/compose/compose.telemetry.yml` and `docker/langfuse/docker-compose.yml`, ensuring OTLP spans are ingested directly to ClickHouse in real time without delayed buffering.

6. **Automated Verification & Test Harnesses**:
   - Created `packages/brainsOS-agent/tests/test_langfuse_trace.py` with 12 unit tests covering trace ID derivation, trace naming, OTLP payload formatting, error handling, truncation, and provider plugin flags.
   - Updated `scripts/verify/verify-email-runs.sh` to assert that the thread trace contains both the worker `email-run` span and `Hermes turn`, verifying zero duplicate LiteLLM generations on the thread trace.
   - Updated `scripts/verify/verify-langfuse.sh` to enforce `langfuse_otel` and reject legacy `langfuse`.
   - Updated `README.md` to document the unified Langfuse tracing architecture.
