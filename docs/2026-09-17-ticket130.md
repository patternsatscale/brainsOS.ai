## 1. Summary of Changes

This change formalizes the operational and structural boundary between documentation/supervision/critique and coding agent instructions, incorporates static UI assets from Stitch, and establishes strict execution preconditions.

### A. Repository Operating Discipline (`AGENTS.md`)
- **Rule 11 (Separation of Build and Record)**: Codified that `docs/lab-work/` is the documentation and critique working area owned by Claude on behalf of the maintainer. Coding agents must never read it for requirements, write to it, refactor it, or include it in ticket scopes. Work orders originate strictly from GitHub Issues.
- **Rule 12 (Sub-Agent Persona Isolation & Code Quality Protection)**: Preserved and decoupled sub-agent persona hierarchy and automated quality gates from ticket #106.
- **Rule 13 (Execution Environment Precondition & Doc-Only Verification Exemption)**:
  - **Mandatory `.env` Precondition**: If no `.env` file exists on the host, the machine is strictly an unconfigured repository clone and must NEVER run test scripts, background daemons, or docker containers.
  - **Doc-Only Exemption**: Pure documentation tasks (`docs/`, `*.md`) and static asset additions are strictly exempt from runtime test script executions.
- **Step 4 Updated**: Added documentation-only exemption and environment checks to verification workflow.
