## 2. Acceptance Criteria Verification

- [x] **Bawtford, Marvin, and Cindy Pawford can be invoked consecutively through the same running container without state bleeding**:
  - Validated by `test_consecutive_multi_agent_invocation_no_state_bleeding`: Consecutive requests for Bawtford and Marvin dynamically hydrate their respective personas and working memory without cross-contamination.
- [x] **Hermes executes its tool-calling loop and returns the final response payload to the adapter**:
  - Validated by `test_tool_calls_extraction`: Extracts tool calls and metadata into `OutboundEmail.metadata["tool_calls"]` and formats final assistant text.
- [x] **Idle RAM overhead remains constant regardless of how many agents are configured in `config/agents.yaml`**:
  - Verified by single warm container topology (`hermes-runner` service on port 8642) replacing the dynamic container-per-agent topology.
- [x] **Tool executions cannot read or mutate files outside `data/agent_workspaces/<agent_id>`**:
  - Validated by `test_workspace_isolation_boundaries`: `validate_workspace_path()` rejects path traversal (`../marvin/secret.txt`) and absolute host root escapes (`/etc/passwd`).
- [x] **Rule 2 (Inference Boundary)**:
  - Completions route strictly through LiteLLM (`LITELLM_URL=${LITELLM_URL:-http://host.docker.internal:4000/v1}`).
- [x] **Rule 7 (Compartmentalization)**:
  - System prompts avoid mentioning raw host daemon names or socket paths, injecting only assigned identity and isolated `/workspace` and `/memories` paths.
- [x] **Rule 12 (Sub-Agent Persona Isolation)**:
  - Persona files are loaded directly from disk without embedding roleplay meta-artifacts or conversational banter into generated code.
