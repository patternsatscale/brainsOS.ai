## 1. Summary of Changes

This ticket resolves Operator IDE configuration drift, eliminates hardcoded model arrays in Code-Server by shifting entirely to dynamic LiteLLM virtual key model discovery, establishes automated host model synchronization for Ollama, and delivers the Obsidian Cybernetic theme for mitmweb:

1. **LiteLLM Fleet Virtual Key DB Provisioning**:
   - Updated [scripts/control/start-control-plane.sh](file:///home/patternsatscale/brainsOS/os/scripts/control/start-control-plane.sh) to automatically and idempotently provision all active fleet virtual keys into LiteLLM PostgreSQL DB upon launch:
     - `OPERATOR_LITELLM_KEY` (alias: `brainsos-operator`, max budget $100.0)
     - `TERRASTELLA_LITELLM_KEY` (alias: `brainsos-terrastella`)
     - `MARVIN_LITELLM_KEY` (alias: `brainsos-marvin`)
     - `BAWTFORD_LITELLM_KEY` (alias: `brainsos-bawtford`)
     - `HERMES_LITELLM_KEY` (alias: `hermes-agent`, backward compatibility)
   - Resolves the `401 Unauthorized: token_not_found_in_db` error that previously broke in-container `make models` and Copilot/chatLanguageModels.json connectivity.

2. **Dedicated Host Model Synchronization (`scripts/setup/setup-models.sh`)**:
   - Created [scripts/setup/setup-models.sh](file:///home/patternsatscale/brainsOS/os/scripts/setup/setup-models.sh) to idempotently check, pull, and synchronize required LLM weights into local Ollama:
     - Automatically parses `BRAINSOS_CORE_MODEL` (e.g. `llama3.2:3b`) and `INFERENCE_MODEL` (e.g. `gemma2:2b`) from `.env`.
     - Supports `--check` for non-destructive inspection, `--all` for complete fleet models, and `--model <name>` for targeted pulls.
     - Integrated into [scripts/control/start-control-plane.sh](file:///home/patternsatscale/brainsOS/os/scripts/control/start-control-plane.sh) (Step 1.5) so missing core models are automatically pulled on control plane launch.
     - Integrated into [scripts/setup/setup-host.sh](file:///home/patternsatscale/brainsOS/os/scripts/setup/setup-host.sh) (Step 6) and [scripts/control/bootstrap-env.sh](file:///home/patternsatscale/brainsOS/os/scripts/control/bootstrap-env.sh) (Step 4.5, `make setup`).
     - Added `make models-pull` and `make models-check` to [Makefile](file:///home/patternsatscale/brainsOS/os/Makefile).

3. **100% Dynamic Virtual Key Model Discovery (Zero Hardcoded Models)**:
   - Completely removed all static model definitions and dictionaries from [config/editor/settings.json](file:///home/patternsatscale/brainsOS/os/config/editor/settings.json), [config/editor/brainsos.code-workspace](file:///home/patternsatscale/brainsOS/os/config/editor/brainsos.code-workspace), and [docker/editor/entrypoint.sh](file:///home/patternsatscale/brainsOS/os/docker/editor/entrypoint.sh).
   - Removed `customendpoint` from [config/editor/chatLanguageModels.json](file:///home/patternsatscale/brainsOS/os/config/editor/chatLanguageModels.json), keeping strictly the dynamic `litellm-connector` block:
     ```json
     [
       {
         "name": "LiteLLM",
         "vendor": "litellm-connector",
         "baseUrl": "http://litellm:4000",
         "apiKey": "${OPERATOR_LITELLM_KEY}"

     ```
   - Code-Server now delegates 100% of model enumeration to LiteLLM via the operator's virtual key. As models are added, changed, or rotated in LiteLLM or Ollama, Code-Server updates its model picker dynamically with zero file edits or container restarts.

4. **Code-Server Explorer Sidebar Pruning**:
   - Pruned and collapsed default clutter views in the Explorer view container across [config/editor/settings.json](file:///home/patternsatscale/brainsOS/os/config/editor/settings.json) and [config/editor/brainsos.code-workspace](file:///home/patternsatscale/brainsOS/os/config/editor/brainsos.code-workspace):
     - `"explorer.openEditors.visible": 0` (hides Open Editors panel)
     - `"outline.collapseItems": "alwaysCollapse"`, `"outline.showProblems": false`
     - `"timeline.excludeSources": ["*"]`
     - `"npm.exclude": ["**"]`
     - `"foam.orphans.exclude": ["**/*"]`, `"foam.placeholders.exclude": ["**/*"]`
   - Patched `foam.foam-vscode`'s `package.json` in [docker/editor/Dockerfile](file:///home/patternsatscale/brainsOS/os/docker/editor/Dockerfile) and [docker/editor/entrypoint.sh](file:///home/patternsatscale/brainsOS/os/docker/editor/entrypoint.sh) to set `"when": "false"` on all 7 Foam explorer views (`foam-vscode.connections`, `tags-explorer`, `notes-explorer`, `orphans`, `placeholders`, `smart-folders`, `related-notes`).
   - Enhanced the `brainsos.system-terminal` custom extension ([config/editor/extensions/brainsos-system-terminal/extension.js](file:///home/patternsatscale/brainsOS/os/config/editor/extensions/brainsos-system-terminal/extension.js)) to automatically issue `.removeView` commands on startup to keep the Explorer sidebar focused strictly on `/data`.

5. **Mitmproxy (`efw`) Obsidian Cybernetic Dark Theme**:
   - Created [docker/egress/Dockerfile](file:///home/patternsatscale/brainsOS/os/docker/egress/Dockerfile) based on `mitmproxy/mitmproxy:latest` that bakes [config/egress/theme/brainsos-mitmweb.css](file:///home/patternsatscale/brainsOS/os/config/egress/theme/brainsos-mitmweb.css) directly into mitmweb static assets and `index.html` at build time with root permissions.
   - Updated [docker-compose.yml](file:///home/patternsatscale/brainsOS/os/docker-compose.yml) to build `tool-egress-proxy` from the Dockerfile.
   - Updated [config/egress/addons/theme_loader.py](file:///home/patternsatscale/brainsOS/os/config/egress/addons/theme_loader.py) to detect pre-baked assets and avoid permission errors when running as unprivileged user `mitmproxy`.

6. **Tool & Function Calling Capabilities Resolution**:
   - Diagnosed why `qwen3.8:latest` was not flagged with tool capabilities: LiteLLM maintains a built-in static model dictionary (`model_prices_and_context_window.json`). Standard models like `qwen2.5` or `llama3.2` are recognized automatically, but custom or non-standard local Ollama tags (like `qwen3.8:latest`) return `null` for `supported_openai_params` and `supports_function_calling` on `/model/info`.
   - VS Code's `gethnet.litellm-connector-copilot` evaluates `supportsTools = (supported_openai_params.includes("tools") || supports_function_calling === true)`.
   - **Dual-Layer Fix**:
     1. Configured explicit `model_info` in [config/litellm/config.yaml](file:///home/patternsatscale/brainsOS/os/config/litellm/config.yaml) with `supports_function_calling: true`, `supports_tool_choice: true`, and `supported_openai_params: ["tools", "tool_choice", "functions", ...]`. Verified live that `/model/info` now explicitly reports tool capabilities.
     2. Configured `"litellm-connector.modelCapabilitiesOverrides"` in [config/editor/settings.json](file:///home/patternsatscale/brainsOS/os/config/editor/settings.json), [config/editor/brainsos.code-workspace](file:///home/patternsatscale/brainsOS/os/config/editor/brainsos.code-workspace), and [docker/editor/entrypoint.sh](file:///home/patternsatscale/brainsOS/os/docker/editor/entrypoint.sh) to declare `toolCalling` for `qwen3.8:latest`, `brainsos-core`, and `qwen2.5:latest`.

7. **Automated Verification Hardening**:
   - Updated [scripts/verify/verify-editor.sh](file:///home/patternsatscale/brainsOS/os/scripts/verify/verify-editor.sh) to assert dynamic `litellm-connector` discovery, pruned explorer settings, and disabled Foam views.
   - Updated [scripts/verify/verify-tool-egress-proxy.sh](file:///home/patternsatscale/brainsOS/os/scripts/verify/verify-tool-egress-proxy.sh) and [scripts/verify/verify-egress-token-injection.sh](file:///home/patternsatscale/brainsOS/os/scripts/verify/verify-egress-token-injection.sh) to validate `agents.yaml` manifest and dynamic `WEB_PASSWORD` fallback.
