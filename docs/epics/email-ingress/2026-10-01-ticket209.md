## 1. Summary of Changes

Implemented a hybrid, multi-stage cloud infrastructure for inbound external email ingress supporting distinct, fully configurable email domains for testing (OSX laptop) and appliance (DGX box) environments. 

The architecture follows a clean three-tier separation of concerns:
1. **`infra/src/components/`**: Low-level AWS resource primitives grouped by AWS service type (matching the AWS console for single-pane visibility across all buckets, queues, and policies).
2. **`infra/src/functions/`**: Application runtime handlers (CloudFront edge functions, Lambda handlers).
3. **`infra/src/flows/`**: High-level domain workflows that glue components together into cohesive business capabilities.
4. **`infra/sst.config.ts`**: Pure top-level orchestrator that only imports and loads the configured flows.

### Architecture Map

```text
infra/src/
├── components/          # Low-level AWS resource primitives
│   ├── s3.ts            # S3 buckets (ingress bucket with lifecycles, dummy origin)
│   ├── sqs.ts           # SQS queues (ingress queue with SSE & redrive, DLQ)
│   ├── ses.ts           # SES domain identities, DKIM, and inbound receipt rules
│   ├── iam.ts           # Least-privilege IAM policies, users, and credentials
│   ├── dns.ts           # Route 53 hosted zones
│   └── cdn.ts           # CloudFront distributions, ACM certificates, OAC
├── functions/           # Application runtime code
│   └── redirect.ts      # CloudFront edge redirect function
├── flows/               # Domain workflow composition (the glue)
│   ├── email-ingress.ts # Multi-stage email ingress workflow
│   └── public-redirect.ts # Split-horizon DNS & public redirect workflow
└── sst.config.ts        # Pure flow loader
```

### Detailed Component Definitions
- **`infra/src/components/s3.ts`**:
  - `createMailIngressBucket(stage: string)`: Multi-stage S3 bucket (`brainsos-mail-ingress-${stage}`) with default SSE, 100% public access block, SES `s3:PutObject` bucket policy, and strict lifecycle expiration rules (`/raw/*` 7 days, `/approved/*` 14 days, `/quarantine/*` 30 days).
  - `createDummyOriginBucket(subdomain, zoneName)`: CloudFront dummy origin bucket.
- **`infra/src/components/sqs.ts`**:
  - `createMailIngressQueues(stage: string)`: Multi-stage Dead Letter Queue (`brainsos-mail-ingress-dlq-${stage}`) and Ingress Queue (`brainsos-mail-ingress-queue-${stage}`) with SSE-SQS encryption, 14-day retention, 60s visibility timeout, 20s long polling, and redrive policy with `maxReceiveCount: 5`.
- **`infra/src/components/ses.ts`**:
  - `setupSesIdentities(domains, zoneId, zoneName)`: SES domain identities, Easy DKIM, and Route 53 DKIM records.
  - `createMailReceiptRule(stage, ingressDomains, bucketId)`: Multi-stage SES Inbound Receipt Rule Set (`brainsos-mail-ingress-rules-${stage}`) and Receipt Rule delivering raw MIME payloads to S3 `raw/`.
- **`infra/src/components/iam.ts`**:
  - `createMailSanitizerPolicy(stage, bucketArn, queueArn)`: Least-privilege policy for Ticket #210 Lambda to read `/raw/*`, write `/approved/*` & `/quarantine/*`, and enqueue to SQS.
  - `createMailWorkerCredentials(stage, bucketArn, queueArn)`: Least-privilege policy and user for local `brainsOS-mail` consumer strictly allowing SQS receive/delete and S3 `/approved/*` get/delete. Generates access keys.
  - `createSesSenderPolicy()`: Outbound SES send policy.
  - `createCaddyAcmeCredentials(subdomain, zoneId)`: Least-privilege credentials for Caddy ACME DNS-01 challenges.
- **`infra/src/components/dns.ts`**:
  - `setupRoute53Zone(zoneName, createZone)`: Route 53 hosted zone management.
- **`infra/src/components/cdn.ts`**:
  - `setupCloudFrontRedirect(...)`: ACM public certificate, DNS validation, Origin Access Control (OAC), CloudFront distribution, and Route 53 alias record.
- **`infra/src/functions/redirect.ts`**:
  - `createRedirectFunction()` CloudFront edge function for public HTTP/HTTPS redirection.
- **`infra/src/flows/email-ingress.ts`**:
  - Glues S3, SQS, SES, and IAM components into a single callable flow function (`setupEmailIngressFlow`).
- **`infra/src/flows/public-redirect.ts`**:
  - Glues DNS, CDN, S3, and IAM components into a single callable flow function (`setupPublicRedirectFlow`).
- **`infra/sst.config.ts`**:
  - Clean flow-loading manifest, extracting `$app.stage` and custom email domains from `BRAINSOS_EMAIL_DOMAIN` (falling back to `SES_DOMAINS`).
- **`infra/.env.example`** & **`.env.example`**:
  - Documented `BRAINSOS_STAGE` (`osx` vs `dgx`), `BRAINSOS_EMAIL_DOMAIN`, SQS queue URLs, S3 bucket names, and worker credentials.

## 2. Acceptance Criteria Verification

- [x] **SST v3 stack provisions SES Receipt Rule Set, S3 ingress bucket, SQS queue, DLQ, and IAM policies without syntax or synthesis errors**:
  - Verified via TypeScript compiler: `npm run build` in `infra/` passes with 0 type errors across all modular files.
- [x] **S3 bucket has lifecycle rules configured for `/raw/` (7d), `/approved/` (14d), and `/quarantine/` (30d)**:
  - Verified in `infra/src/components/s3.ts` via `aws.s3.BucketLifecycleConfigurationV2` configuring all three prefixes with exact expiration day thresholds.
- [x] **SQS queue has SSE encryption enabled and retention period configured to 14 days**:
  - Verified in `infra/src/components/sqs.ts` with `sqsManagedSseEnabled: true`, `messageRetentionSeconds: 1209600` (14 days), `visibilityTimeoutSeconds: 60`, and redrive policy with `maxReceiveCount: 5`.
- [x] **IAM policy for workstation worker restricts access strictly to SQS receive/delete and S3 `/approved/*` get/delete**:
  - Verified in `infra/src/components/iam.ts`: `workerPolicy` statement explicitly restricts actions to `sqs:ReceiveMessage`, `sqs:DeleteMessage`, `sqs:GetQueueAttributes`, `sqs:ChangeMessageVisibility` on the ingress queue ARN, and `s3:GetObject`, `s3:DeleteObject` on `${ingressBucket.arn}/approved/*`.
- [x] **Support for two distinct email environments (OSX laptop testing vs DGX box)**:
  - Verified via stage parameterization: running SST with `--stage osx` (or `BRAINSOS_STAGE=osx`) provisions `brainsos-mail-ingress-osx`, while `--stage dgx` provisions `brainsos-mail-ingress-dgx`. Domains are configured per machine via `BRAINSOS_EMAIL_DOMAIN`.
- [x] **Hybrid Components & Flows architecture**:
  - Low-level AWS resource primitives reside in `components/`, application code in `functions/`, composition glue in `flows/`, and `sst.config.ts` acts as a clean flow loader.
