## 1. Executive Summary

Ticket #212 completes the local orchestration and container topology integration for external inbound email ingress. We created a hardened, unprivileged container image (`docker/mail/Dockerfile.ingress`) that executes `brainsos-mail-ingress`, wired the `mail-ingress` service into `docker-compose.yml` with strict sandboxing (read-only rootfs, non-root user `1000:1000`, ephemeral tmpfs, zero Docker socket), updated Postfix and Dovecot configurations (`docker/mail/postfix/main.cf`, `docker/mail/entrypoint.sh`, `scripts/setup/setup-mail.sh`) to safely accept local injection for agent domains including `local.brainsos.ai` without requiring SASL credentials, and enforced strict recipient checks preventing external open relay.

End-to-end verification confirmed that local SMTP injection delivered messages directly into agent Maildir storage (`/var/mail/vmail/bawtford/Maildir/`) and executed Dovecot Pigeonhole Sieve filters (`agent-webhook.sh`), spooling raw RFC 822 messages for agent reactive processing.

## 5. Architectural Guardrail Compliance

- **Rule 4 (Host Sandboxing)**: The `mail-ingress` container runs strictly unprivileged as UID/GID `1000:1000` with `no-new-privileges:true`, read-only root filesystem, and zero Docker socket mounts.
- **Rule 5 (Secret Protection)**: All AWS credentials and queue URLs are parameterized via `.env` and `.env.example`, with no secrets committed to Git.
- **Rule 8 (Script-Driven Discipline)**: Service lifecycle and account provisioning are codified within `scripts/setup/setup-mail.sh` and `docker/mail/entrypoint.sh`.
- **Open-Relay Prevention**: Postfix restrictions strictly reject unauthenticated external relay attempts (`554 5.7.1 Relay access denied`), while permitting local injection from container bridge networks for registered agent domains.
