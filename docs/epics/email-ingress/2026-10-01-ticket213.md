## 1. Executive Summary

Ticket #213 establishes the automated, script-first end-to-end verification harness (`scripts/verify/verify-email-ingress.sh`) for the entire external email ingress pipeline. In accordance with **Rule 8 (Script-Driven Discipline)** and **Rule 1 (Memory Plane Purity)**, this harness standardizes automated validation of:
1. The 5-stage AWS Lambda defensive security sanitizer (cryptographic SPF/DKIM verification, sender allowlist enforcement, structural Unicode/hidden HTML stripping, prompt injection heuristics, and security context enveloping).
2. The `brainsOS-mail` ingress submodule (SQS claim-check retrieval, RFC 822 reconstruction, and local SMTP injection).
3. The local mail topology (Postfix local delivery to `/var/mail/vmail/bawtford/Maildir/` and Dovecot Sieve push hooks executing `agent-webhook.sh`).
4. Strict anti-spoofing and prompt injection neutralization.
5. Memory plane purity confirmation asserting zero raw MIME or runtime database artifacts in `/memories`.

The harness supports both `--mock` (fast, reproducible local test matrix using synthetic fixtures without AWS billing or internet dependency) and `--e2e` (live AWS SES/S3/SQS staging stack polling).

## 7. Live Round-Trip Verification & Outbound SES Auto-Reply

Following the initial deployment of the ingress pipeline, two critical gaps were identified and resolved:

### 7.1. Route 53 DMARC & SPF Alignment
- **Issue**: AWS SES flagged `osx.public.brainsos.ai` with a High Impact recommendation: *"DMARC configuration was not found"*.
- **Root Cause**: While Easy DKIM CNAMEs and MX records were configured in `infra/src/components/ses.ts`, corresponding TXT records for SPF and DMARC were missing.
- **Resolution**:
  - Added Route 53 TXT record for SPF: `osx.public.brainsos.ai.` -> `"v=spf1 include:amazonses.com ~all"`
  - Added Route 53 TXT record for DMARC: `_dmarc.osx.public.brainsos.ai.` -> `"v=DMARC1; p=none;"`
  - Re-deployed via `make email-ingress` and verified in Route 53.

### 7.2. Autonomous Outbound SES Auto-Reply (`ping` Mailbox)
- **Issue**: Inbound emails from `patternsatscale@gmail.com` were delivered to `/var/mail/vmail/ping/Maildir/`, spooled via Dovecot Sieve, and sent to `AgentQueueWorkerDaemon` (`http://control-plane:8000/api/v1/mail/inbound`), but the worker skipped processing with `Manifest not found at config/agents.yaml`.
- **Root Cause 1 (Manifest Path Resolution)**: In decoupled fleet mode (Rule 14), `agents.yaml` resides at `${BRAINSOS_DATA_DIR}/settings/agents.yaml` or `config/default_settings/agents.yaml`. The worker defaulted strictly to `config/agents.yaml`, returning an empty profile list.
  - **Fix**: Implemented `resolve_manifest_path()` in `brainsos_agent.config` and wired it into `AgentQueueWorkerDaemon`.
- **Root Cause 2 (SES Outbound Sending)**: Local development workstations cannot deliver directly to external destination MX servers (Gmail) on port 25. Outbound replies to external addresses must route via Amazon SES.
  - **Fix 1 (IAM Permissions)**: Granted `ses:SendEmail` and `ses:SendRawEmail` on `*` in `BrainsOSMailWorkerPolicy` (`infra/src/components/iam.ts`).
  - **Fix 2 (Domain Alignment)**: In `brainsos_agent.worker`, when replying to external recipients or inbound messages from public domains, the sender address is dynamically set to `${profile.id}@${public_domain}` (`ping@osx.public.brainsos.ai`) rather than the private internal domain (`ping@brainsos.local`).
  - **Fix 3 (SES Dispatch in `BrainsOSMailClient`)**: Added `_send_via_ses()` to `brainsos_mail.client` using `boto3.client('ses').send_raw_email()`. External destinations route through SES, while internal destinations route through local Postfix SMTP.
- **Verification Evidence**:
  - Live email from `patternsatscale@gmail.com` processed by `AgentQueueWorkerDaemon`.

### 7.3. Elimination of Duplicate Message Ingestion (Webhook vs. Spool Scanner Race)
- **Issue**: The external operator reported receiving duplicate auto-responder emails delivered to `patternsatscale@gmail.com` (~0.5s apart).
- **Root Cause (Dual Ingestion Race)**:
  1. In `docker/mail/agent-webhook.sh`, incoming Dovecot Sieve pipes wrote `${TIMESTAMP}.eml` into `/var/spool/brainsos/inbound/` and immediately curled `POST /api/v1/mail/inbound`.
  2. `handle_inbound_http` in `AgentQueueWorkerDaemon` wrote its own separate copy `${time.time_ns()}.eml`, enqueued task 1, and created a `.done` sentinel only for that second file.
  3. The background spool scanner loop (`_spool_scanner_loop`) concurrently scanned `/var/spool/brainsos/inbound/` and found the original `${TIMESTAMP}.eml` lacking a `.done` marker. It enqueued it as task 2, causing the auto-responder agent to execute a second turn and dispatch a duplicate outbound SES email.
- **Resolution**:
  1. **Webhook Header Injection**: In `docker/mail/agent-webhook.sh`, passed `--header "X-Spool-Filename: $(basename "${SPOOL_FILE}")"`.
  2. **Single-Spool File Reuse**: In `handle_inbound_http`, if `X-Spool-Filename` is provided and exists on disk, the daemon reuses the existing spool file rather than creating an unlinked duplicate.
  3. **Message-ID Deduplication**: In `AgentQueueWorkerDaemon`, tracked `_processed_message_ids: set[str]`. Duplicate incoming payloads with an already-seen RFC 5322 `Message-ID` are dropped immediately with HTTP 200 `{"status": "ignored", "reason": "duplicate_message_id"}`.
  4. **Scanner Guard**: In `_spool_scanner_loop`, the scanner checks `_processed_message_ids` before enqueueing. If the message was already ingested via HTTP, the scanner marks it `.done` and skips enqueuing.
- **Verification Evidence**:
  - Live email tested by operator; confirmed only a single auto-reply email was received.
