## 7. Master Appliance Identity & Non-Redundant Credential Consolidation

### Architectural Problem Solved
Prior to this enhancement, `.env` and `.env.example` contained redundant, duplicated password definitions across multiple subsystems (`HERMES_DASHBOARD_PASSWORD`, `CODE_SERVER_PASSWORD`, `LANGFUSE_INIT_USER_PASSWORD`, `ADMIN_MAIL_PASSWORD`, `OPERATOR_MAIL_PASSWORD`, `AUTHENTIK_BOOTSTRAP_PASSWORD`, `TOOL_EGRESS_WEB_PASSWORD`), many populated with static placeholders (`brainsos_admin_secret`).

### Clean Architecture & Single Master Credential
1. **Single Master Identity**:
   - `BRAINSOS_ADMIN_USERNAME=admin`
   - `BRAINSOS_ADMIN_EMAIL=admin@{domain}`
   - `BRAINSOS_ADMIN_PASSWORD=<24-char-cryptographically-strong-alphanumeric>`
2. **Zero Redundancy**:
   - Subsystem-specific passwords in `docker-compose.yml`, `scripts/setup/*.sh`, and `scripts/control/*.sh` dynamically fall back to `${BRAINSOS_ADMIN_PASSWORD}`.
   - Redundant keys (`HERMES_DASHBOARD_PASSWORD`, `CODE_SERVER_PASSWORD`, `LANGFUSE_INIT_USER_PASSWORD`, `ADMIN_MAIL_PASSWORD`, `OPERATOR_MAIL_PASSWORD`, `AUTHENTIK_BOOTSTRAP_PASSWORD`, `TOOL_EGRESS_WEB_PASSWORD`, `OPERATOR_PASSWORD_HASH`) are pruned from `.env` by `generate-env.sh`.
3. **Cryptographic Generation with Zero Placeholders**:
   - `scripts/control/generate-env.sh` generates high-entropy random secrets for all unconfigured keys (`gen_alphanumeric(24)` for admin password, `gen_hex(20)` for PostgreSQL databases, `gen_hex(32)` for Authentik secret keys).
   - Zero `"change_me"` or `"brainsos_admin_secret"` strings remain in `.env`.
4. **Dynamic Database Credential Synchronization (`scripts/control/reload-env.sh`)**:
   - `LiteLLM DB`: `ALTER USER "litellm" WITH PASSWORD ...`
   - `SOGo DB`: `ALTER USER "sogo" WITH PASSWORD ...` + `sogo_users` table credential updates for `admin`, `operator`, `akadmin`.
   - `Authentik DB`: `ALTER USER "authentik" WITH PASSWORD ...` + Django ORM user password updates for `admin`, `akadmin`, `operator`.
   - `Langfuse DB`: `ALTER USER "langfuse" WITH PASSWORD ...` + BCrypt hash synchronization for admin account.
   - `Caddy Ingress`: Dynamic bcrypt hash generation (`caddy hash-password`) synchronized to `OPERATOR_PASSWORD_HASH`.
   - `SOGo In-Container Templating`: `docker/sogo/sogo.conf.template` rendered dynamically into `/etc/sogo/sogo.conf` with live `${DB_PASS}` and `${MAIL_DOMAIN}` on container startup.
