## 1. Executive Summary

This ticket configures single-sign-on access for the LiteLLM Control Plane UI (`/proxy/ui/`) and Langfuse Distributed Tracing (`langfuse.*`) via Authentik Forward-Auth, injecting master authorization tokens where required for seamless operator entry:
1. **LiteLLM Master Key Injection & Login Capture**: Configured Caddy's `/proxy/ui/*` and `/ui*` reverse proxy blocks with `header_up Authorization "Bearer {$LITELLM_MASTER_KEY}"`, allowing the operator to inspect models, virtual keys, and budgets without manual token entry, and capturing LiteLLM's internal `/ui/login/` flow.
2. **Langfuse Subdomain Ingress & Identity Propagation (Option A)**: Routed `langfuse.*` through Caddy with `(authentik_forward_auth)` and forwarded Authentik user identity headers (`X-Authentik-Username`, `Remote-User`, `Remote-Email`). Stripped `X-Frame-Options` and CSP frame-ancestors for seamless portal iframe embedding.
3. **Subpath Forwarding**: Any request to `https://osx.local.brainsos.ai/langfuse/` cleanly returns HTTP 302 redirecting to `https://langfuse.osx.local.brainsos.ai/`.
4. **Control Plane Security Guardrail (Rule 6)**: The dedicated LiteLLM PostgreSQL store (`brainsos-infra-litellm-db`) remains completely isolated on `brainsos-litellm-net` and is unreachable from agent containers.
