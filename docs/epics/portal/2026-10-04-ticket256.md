## 1. Executive Summary

This ticket consolidates the Caddy reverse-proxy ingress topology into the **3-Plane Ingress Model**, transitions the appliance from fragile subdomains to a single-origin path topology (`https://osx.local.brainsos.ai/*`), and fixes the critical subpath routing and permission blockers that caused `/editor`, `/ui/login/`, and observability traces to fail:

1. **3-Plane Ingress Model**:
   - **Plane 1 (Browser UI & Portal)**: Unified single-origin host (`local.brainsos.ai`, `osx.local.brainsos.ai`) serving the React Thin-Spine Portal at `/`, with Authentik forward-auth protecting `/editor/`, `/mail/`, `/proxy/ui/`, `/ui/`, `/efw/`, `/langfuse/`, and `/auth/`.
   - **Plane 2 (Programmatic APIs)**: Direct reverse-proxy for `proxy.*` hostnames and `/v1/*` paths to LiteLLM (port 4000) preserving client Bearer tokens without SSO interference.
   - **Plane 3 (Mail Ingress & Discovery)**: Dedicated `mail.*` host for CalDAV/CardDAV redirects (`.well-known`) and SOGo WebObjects proxying.
   - **Plane 4 (Observability Ingress)**: Dedicated `langfuse.*` host handling Next.js trace assets and API websockets, plus path routing under `/langfuse/`.
2. **Subpath Trailing-Slash Normalization & Prefix Stripping**:
   - Added `308 Permanent Redirect` handlers for unslashed paths (`/editor` -> `/editor/`, `/efw` -> `/efw/`, `/proxy/ui` -> `/proxy/ui/`, `/langfuse` -> `/langfuse/`) so browser relative asset resolution stays anchored to the subpath.
   - Configured `uri strip_prefix` in Caddy for `/editor/*` (so `code-server:8443` receives root `/` without returning `405 Method Not Allowed`), `/proxy/ui/*` (so LiteLLM receives `/ui/*`), and `/langfuse/*` (so Langfuse receives root `/`).
   - Routed `/litellm-asset-prefix/*` to LiteLLM to serve Next.js static asset chunks.
   - Added `/ui*` route in Caddy so LiteLLM's internal `/ui/login/?redirect_to=...` flow routes directly to LiteLLM's login engine rather than rendering a blank portal fallback.
3. **Upstream Credential Injection**:
   - Injected `Authorization: Bearer {$TOOL_EGRESS_WEB_PASSWORD}` into Caddy's `/efw/*` reverse proxy block, providing seamless access to the mitmweb console without password prompts.
   - Injected `Authorization: Bearer {$LITELLM_MASTER_KEY}` for the LiteLLM Admin UI on `/proxy/ui/*` and `/ui*`.
   - Forwarded `x-webobjects-remote-user` for SOGo Trusted Proxy Authentication.
4. **Code-Server Startup Hardening**:
   - Updated [`docker/editor/entrypoint.sh`](file:///Users/pats/Development/brainsOS.ai/docker/editor/entrypoint.sh) to execute `/usr/bin/code-server` directly, bypassing `fixuid` setuid failures under the container's `no-new-privileges:true` security profile.
5. **Real-World Live Verification**:
   - Completely upgraded [`scripts/verify/verify-portal.sh`](file:///Users/pats/Development/brainsOS.ai/scripts/verify/verify-portal.sh) and [`scripts/verify/verify-editor.sh`](file:///Users/pats/Development/brainsOS.ai/scripts/verify/verify-editor.sh) to perform live `curl` assertions with TLS SNI resolution against running containers instead of static string grepping.

## 5. Architectural Invariants & Observability Resolution

### The Langfuse Observability Invariant (Option A Selected)
- **Problem**: Langfuse is an upstream prebuilt Next.js application (`docker.langfuse.com/langfuse/langfuse:4.38.0`). Next.js hardcodes root-relative asset URLs (`/_next/static/...`, `/api/auth/...`) at compile time. Running Langfuse under a subpath like `/langfuse/` results in broken JavaScript chunk loading and API collisions with Authentik's `/api/*`.
- **Resolution**:
  1. Maintained dedicated subdomain ingress: `https://langfuse.osx.local.brainsos.ai/` (and `langfuse.local.brainsos.ai`), resolved automatically by existing wildcard DNS (`*.local.brainsos.ai -> 127.0.0.1`).
  2. Configured Caddy `@langfuse_path` redirect: Any navigation to `https://osx.local.brainsos.ai/langfuse` or `/langfuse/` cleanly returns HTTP 302 redirecting to `https://langfuse.{host}/`.
  3. Configured Caddy to strip `X-Frame-Options` and `Content-Security-Policy` from Langfuse responses, enabling full-featured in-portal iframe embedding without rendering errors.
  4. Updated `packages/brainsOS-portal`'s `ViewportFrame` to dynamically compute `liveUrl` pointing to `https://langfuse.${window.location.hostname}/`.
  5. Authentik SSO is shared across all subdomains via wildcard cookie domain (`.local.brainsos.ai`), ensuring single-sign-on without secondary authentication prompts.
