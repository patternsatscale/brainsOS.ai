## 1. Summary of Changes

| File | Change |
|------|--------|
| `scripts/control/update.sh` | **Rewritten & Hardened.** Enforced Rule 13 (requires `.env`, exits immediately if missing, zero `.env.example` sourcing). Exports `COMPOSE_FILE` honoring appliance overlay (`compose.appliance.yml`). Resolved running versions via `docker compose config --format json` and `docker inspect` (eliminating bash expansion artifacts like `"-v1.105.0}"`). Removed hardcoded Caddy/Hermes versions (reporting `"local build"`). Added `--version <tag>` targeting via `env-upsert.sh` and `--reset-version` to restore pinned defaults. Implemented in-network health probes (`pg_isready` across all Postgres instances, LiteLLM `/health/liveness`, Langfuse `/api/public/health`, and Caddy non-5xx response) with configurable `--health-timeout` (default 30s). Hardened rollback trap: restores pre-update `.env`, safe Git restoration (never `reset --hard`), restores pre-flight data snapshot, and re-aligns containers. Added unattended dirty repo guardrail (Audit #18). |
| `scripts/control/backup.sh` | **Refactored & Hardened.** Enforced Rule 13 (fails closed if `.env` is missing, no `.env.example` fallback). Replaced raw data directory copying of `DB_DIR` over live databases with logical `pg_dump` dumps for all running Postgres containers (`litellm-db`, `langfuse-db`, `authentik-db`, `sogo-db`) via in-container credentials (Rule 6). On restore: stops dependent services before restore, cleans schemas, streams dumps, and restarts dependents. Removed outdated delegation to `data/backups/backup.sh`. Supported `--restore latest` archive auto-resolution. |
| `packages/brainsOS-appliance/tests/test_update_engine.py` | **New.** 6 automated tests covering Rule 13 missing `.env` rejection in `update.sh` and `backup.sh`, clean semver reporting in `update.sh --check --json`, version targeting & reset dry-run plans, appliance overlay port lockdown regression, and unattended dirty repository rejection. |

## 2. Acceptance Criteria Verification

### C1: Appliance Awareness (Audit #12)
- [x] All `docker compose` invocations honor `COMPOSE_FILE` exported from `.env`. Regression test `test_appliance_compose_overlay_port_lockdown_with_update` verifies zero internal services expose host ports when merged with `compose.appliance.yml`.
- [x] Health probes run in-network (`docker compose exec` for `pg_isready`, LiteLLM python probe on `127.0.0.1:4000`, Langfuse node probe on `127.0.0.1:3000`), operating correctly without published host ports.

### C2: Version Detection & Targeting (Audit #13, #14)
- [x] Resolved running versions from `docker compose config --format json` and `docker inspect`.
- [x] Clean semver reporting: verified `1.105.0` for LiteLLM and `4.58.0` for Langfuse (zero `"-v1.105.0}"` interpolation artifacts).
- [x] Removed hardcoded Caddy (`2.8.4`) and Hermes (`1.0.0`) versions; reports `"local build"` accurately.
- [x] `--service <name> --version <tag>` persists the tag via `.env` overrides (`LITELLM_IMAGE_TAG`, `LANGFUSE_IMAGE_TAG`, `CADDY_IMAGE_TAG`), pulls, and recreates.
- [x] `--service <name> --reset-version` (or `--reset`) removes the override via `env-upsert.sh --unset` and recreates with the pinned default.

### C3: Health Verification (Audit #16)
- [x] Probes in-network `pg_isready` for each Postgres container (`litellm-db`, `langfuse-db`, and `authentik-db` / `sogo-db` if running).
- [x] Probes LiteLLM `/health/liveness` in-network.
- [x] Probes Langfuse `/api/public/health` in-network.
- [x] Probes Caddy expecting a non-5xx response (`< 500`).
- [x] Configurable probe window via `--health-timeout` (default 30s).

### C4: Safe Snapshot & Rollback (Audit #15)
- [x] Pre-flight records container image IDs for rollback alignment.
- [x] Database snapshots use logical `pg_dump` via `docker compose exec` using in-container credentials (never CLI arguments, Rule 6) covering all Postgres instances.
- [x] Zero raw database directory copying over live databases.
- [x] Backup failure aborts update (unless `--no-backup`); errors are never swallowed.
- [x] Rollback handler restores pre-update `.env`, restores pre-flight data snapshot, stops dependent services before restore, and restores container state.

### C5: Preconditions & Git Safety (Audit #17, #18)
- [x] Missing `.env` exits immediately with code 1 and logs Rule 13 error. Never sources `.env.example`.
- [x] Refuses to update a dirty git repository in unattended mode (`-y`), exiting with code 1.
- [x] Safe git rollback: uses `git checkout` / `git reset --keep` (never `reset --hard`) to prevent data loss over operator edits.
