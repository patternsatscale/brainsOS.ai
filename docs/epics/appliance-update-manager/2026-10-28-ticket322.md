**`build-ami.sh` behaviour:**

- `--ref` defaults to the latest `v*` tag.
- Refuses a dirty working tree unless `--allow-dirty` is passed.
- Stages a shallow git clone of exactly one commit, with `origin` set to the public remote.
- Checks that the ref contains the appliance package.
- Runs a fail-closed `--scan-only` pass before Packer.
- Pre-flights: AWS CLI, `sts`, `session-manager-plugin`, Block Public Access.
- `--promote <ami-id>` checks Block Public Access, availability and that no snapshot is encrypted, then sets launch permission and verifies `Public=True`.

**`provision.sh` behaviour:**

- Installs `make`, `nodejs`, `npm` and `socat`, and exactly one SSM agent.
- Pre-builds every image with `make runner-base build` and `compose pull` (no `--ignore-pull-failures`), then verifies each image exists locally.
- Builds the portal and creates `.venv` through `bootstrap-env.sh`.
- Sanitizes: `authorized_keys`, host keys, `.env*`, `data/`, uv/pip caches, git hook, machine-id, cloud-init state, histories.
- Ends with a fail-closed scan.

**`firstboot.sh` behaviour:**

- Calls `generate-env.sh --force-passwords` only when no `.env` exists.
- The instance ID is used only for the operator login (`BRAINSOS_ADMIN_PASSWORD`, `AUTHENTIK_BOOTSTRAP_PASSWORD`).
- Generates random service, ClickHouse and OIDC secrets.
- Writes `COMPOSE_FILE`, `LITELLM_CONFIG`, `OLLAMA_ENABLED=false` and the region into `.env`.
- Seeds `data/` with `bootstrap-env.sh`; a failure here is fatal.
- The banner no longer prints the password and asks the operator to rotate it.
- Warns when the region is outside the US.

## 2. Acceptance Criteria Verification

- [x] **A1: ref, dirty-tree refusal, clean staging, fail-closed scan.**
  - `--ref` defaults to `git describe --tags --match 'v*'`.
  - A dirty tree is refused.
  - The artifact is a `git fetch --depth 1` of one commit, so untracked `.env` and `data/` can never be included.
  - `provision.sh --scan-only` runs on the staged tree before Packer and again on the host before the snapshot.
  - Tests: `test_build_ami_*` and `test_snapshot_scan_*`.
- [x] **A2: SSH keys scrubbed; SSM communicator.**
  - `authorized_keys` and `/etc/ssh/ssh_host_*` are deleted, and the scan rejects them if they remain.
  - `ssh_interface = "session_manager"`, using a temporary SSM instance profile.
- [x] **A3: unique secrets.**
  - Firstboot uses `generate-env.sh`.
  - `test_firstboot_generates_unique_secrets_not_equal_to_compose_defaults` checks that no secret-like value equals any `${VAR:-default}` in the compose files.
  - `test_firstboot_secrets_differ_between_instances` checks that two instances get different secrets.
  - The instance ID is used only for operator login, and the banner tells the operator to rotate it.
  - `Requires=`/`After=brainsos-firstboot.service` is set.
- [x] **A4: `.env` carries the topology; unit uses `reload-env.sh`.** `COMPOSE_FILE` and `LITELLM_CONFIG` are in `.env`. `brainsos.service` runs `reload-env.sh --no-urls` with `HOME=/root`.
- [x] **A5: images and portal pre-built.** `make runner-base build`, `compose pull --ignore-buildable` (fails on any error), an image presence check, and `setup-portal.sh`.
- [x] **A6: IMDS, Bedrock IDs, IAM policy.** `imds_support = "v2.0"`. Bedrock IDs refreshed (see the follow-up below). `iam/instance-policy.json` added and documented.
- [x] **A7: BPA pre-flight and promote.** The Block Public Access check runs before `--publish-community` and `--promote`. `build-ami.sh --promote <ami-id>` is implemented.
- [x] **A8: dead fallbacks removed; ruff clean.** The `appliances/` fallbacks are gone and `ruff check packages/brainsOS-appliance` passes.

## 4. Follow-Ups / Backlog

1. **New release tag required.** `v0.1.0` predates the appliance package. After #321 merges, tag (for example) `v0.1.1` before the #320 rehearsal.
2. **Verify Bedrock IDs in #320.** Run `aws bedrock list-inference-profiles --region us-east-1` and invoke each alias through LiteLLM. Enable model access in the console.
3. **Forced password rotation.** Only the banner and docs exist today. A real expiring-password flow in the Authentik operator stage is a backlog item.
4. **Dev-host secret generation.** `generate-env.sh` does not emit `CLICKHOUSE_PASSWORD` or `AUTH_*_CLIENT_SECRET`, because they are not in `.env.example`. Only appliances override them. Adding them for dev hosts needs a migration for existing ClickHouse volumes.
5. **Firstboot network dependency.** `bootstrap-env.sh` re-validates `.venv` with `uv`, which may reach PyPI. Consider an offline wheel cache.
6. **Scope boundaries.**
   - #323: TLS/Caddyfile selection, BYOD, Langfuse upstream.
   - #324: update engine.
   - #325: System API/UI.
