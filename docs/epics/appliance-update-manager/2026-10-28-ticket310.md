## 2. Acceptance Criteria Verification

- [x] **`scripts/control/update.sh` implementation**:
  - Implemented supporting `--check`, `--containers-only`, `--full`, `--service <name>`, `--unattended`, `--dry-run`, and `--json`.
  - Tested CLI version status table rendering and JSON serialization.
- [x] **Pre-flight snapshot integration**:
  - Automatically invokes `scripts/control/backup.sh --backup` before applying container or git updates.
  - Registers the created tarball for point-in-time recovery.
- [x] **Source code update logic**:
  - Evaluates git status, stashes untracked/dirty changes safely, pulls latest tracking branch (`git pull --ff-only`), syncs dependencies via `uv`, and rebuilds portal static bundle if needed.
- [x] **Container update logic**:
  - Pulls latest upstream container images (`docker compose pull`) and gracefully recreates services (`docker compose up -d`).
  - Supports targeting single services (e.g. `--service litellm`) or all services.
- [x] **Post-flight health verification & self-healing rollback**:
  - Probes Caddy ingress (ports 80/443), LiteLLM gateway (`/health/liveness`), and Postgres database (`pg_isready`).
  - Automatically triggers rollback if any healthcheck fails within 30 seconds: reverts Git ref, restores `backup.sh --restore <archive> -f`, and restarts containers.
- [x] **Root Makefile targets**:
  - Added `make update` and `make update-check` to root `Makefile` and `.PHONY`.
- [x] **Telemetry API endpoints**:
  - Implemented `GET /api/v1/system/status` and `POST /api/v1/system/update` streaming live stdout/stderr via Server-Sent Events (SSE).
