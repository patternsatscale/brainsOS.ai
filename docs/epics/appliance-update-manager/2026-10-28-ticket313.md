## 1. Summary of Changes

This ticket establishes the automated, declarative HashiCorp Packer pipeline for packaging brainsOS into an Amazon Machine Image (AMI) targeting ARM64 Graviton instances (`t4g.medium`, `c7g`, `m7g`). In alignment with repository modularity and user direction, all appliance code and configuration has been organized and isolated into a dedicated Python package: **`packages/brainsOS-appliance`**.

Key architectural deliverables include:
1. **Isolated Package (`packages/brainsOS-appliance`)**: Dedicated structure containing Packer HCL templates, shell provisioners, systemd unit templates, cloud-init first-boot engine, host hardening baseline, CLI utilities, and unit test suite.
2. **Declarative Packer Templates (`packages/brainsOS-appliance/packer/`)**: `brainsos-ami.pkr.hcl` and `variables.pkr.hcl` configuring the `amazon-ebs` builder on Ubuntu 24.04 ARM64 with IMDSv2 token enforcement (`http_tokens = "required"`), zero-inbound SSH, and parameterizable community publishing.
3. **Automated Shell Provisioner (`provision.sh`)**: Installs Docker CE, Docker Compose, AWS Systems Manager (SSM) Agent, and `uv`, syncs repository code to `/opt/brainsos`, executes perimeter hardening, pre-pulls platform container images, and sanitizes machine-id/logs before snapshotting.
4. **First-Boot Cloud-Init Engine (`firstboot.sh` & `brainsos-firstboot.service`)**: Queries AWS IMDSv2 securely for instance identity, enforces the AWS Marketplace credential invariant (`BRAINSOS_ADMIN_PASSWORD = instance-id`), provisions dynamic `.env` with strict `0600` permissions, and self-disables after initial initialization.
5. **Systemd Lifecycle Daemon (`brainsos.service`)**: Manages Docker Compose appliance startup and shutdown across VM reboots.
6. **LiteLLM Bedrock Catalog (`config/litellm/config.bedrock.yaml`)**: Routes models via AWS Bedrock (`claude-3-5-sonnet`, `claude-3-haiku`, `llama3-70b`, `amazon-nova-pro`) using ambient EC2 IAM role credentials without hardcoded API keys.
7. **Wrapper CLI & Makefile Integration**: Created `scripts/control/build-ami.sh` and added `make build-ami` supporting `--dry-run`, `--validate-only`, `--region`, and `--publish-community`.

## 4. Architectural Guardrails Verification

- **Rule 1 (Memory Plane Purity)**: No SQLite databases, packages, or cache files reside within `/memories`.
- **Rule 4 & 6 (Host Sandboxing & DB Isolation)**: Inbound SSH (port 22) is completely closed in the appliance profile; operator administration operates strictly through outbound AWS SSM Session Manager.
- **Rule 8 (Script-Driven Discipline)**: All operational workflows (AMI build, first-boot initialization, perimeter hardening) are codified as reproducible shell scripts (`firstboot.sh`, `harden-host.sh`, `provision.sh`, `build-ami.sh`).
- **Rule 10 (Zero Ambient Secrets)**: No credentials, passwords, or temporary SSH keys are baked into the AMI snapshot. Initial administrative password is dynamically generated from `instance-id` on initial boot.
- **Rule 14 (Two-Repository Architecture)**: All platform templates and packages resolve paths dynamically without hardcoded absolute directories or symlinks.
