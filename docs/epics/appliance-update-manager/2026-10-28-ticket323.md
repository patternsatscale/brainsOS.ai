## 2. Acceptance Criteria Verification

### B1: Runtime Caddyfile Selection
- [x] `docker/compose/compose.ingress.yml` selects `CADDYFILE` dynamically with fallback to `Caddyfile`.
- [x] Appliance mode explicitly injects `CADDYFILE=Caddyfile.appliance`.
- [x] Caddy container command validates selected file against an allowlist before execution.

### B2: Default Internal CA Configuration
- [x] Removed bare `:443` block from `Caddyfile.appliance`.
- [x] Defined explicit site addresses for `{$BRAINSOS_DOMAIN:localhost}`, subdomains (`langfuse.*`, `proxy.*`, `mail.*`), and `{$BRAINSOS_IP_SITES:127.0.0.1}`.
- [x] Added `default_sni {$BRAINSOS_DOMAIN:localhost}` for non-SNI bare IP requests.
- [x] Configured dynamic snippet import: `import tls_{$BRAINSOS_TLS_MODE:internal}`.
- [x] Snippets defined: `(tls_internal)`, `(tls_acme)`, `(tls_route53)`.
- [x] Every defined snippet is imported; zero unimported dead snippets exist.
- [x] Port 80 retains 301-redirect to HTTPS on all hosts.
- [x] Added authenticated `/system/ca.crt` route serving `/data/caddy/pki/authorities/local/root.crt`.
- [x] First-boot banner documents CA download endpoint and `set-domain.sh` pointer.
- [x] `trust-caddy-ca.sh` supports `--export` and `--help` flags.

### B3: Bring-Your-Own-Domain (BYOD) Public ACME Upgrade Path
- [x] `firstboot.sh` extracts `BRAINSOS_DOMAIN`, `ACME_EMAIL`, and `BRAINSOS_TLS_MODE` from EC2 user-data (supporting YAML `#cloud-config` and `KEY=VALUE` formats).
- [x] `scripts/control/set-domain.sh` provides CLI with `--domain`, `--email`, `[--dns route53]`, `--internal`, `--dry-run`, `--skip-dns-check`, and `--force`.
- [x] Added `make set-domain` target to `Makefile`.
- [x] ACME and Route 53 snippets define `issuer internal` fallback to prevent ingress failure during DNS propagation or rate limits.
- [x] `show-urls.sh` inspects active TLS cert and surfaces ACME fallback warning when applicable.

### B4: Single-Hostname Routing & Upstream Consistency
- [x] `LANGFUSE_UPSTREAM` in both Caddyfiles defaults to in-network `langfuse-web:3000` rather than `host.docker.internal:3001`.
- [x] Path-based `/api/v1/system/*` and `/system` portal routes preserved on single hostname.
- [x] Zero host ports exposed for internal services.

## 4. Local Web Preview URLs & Verification Instructions

To test the ingress and TLS configuration locally:

1. **Verify Root CA Endpoint**:
   - URL: `https://localhost/system/ca.crt`
   - Authenticate with operator credentials (Authentik session). The browser will prompt to download `caddy_root.crt`.
2. **Verify System Portal**:
   - URL: `https://localhost/system`
   - Test portal rendering, system status navigation, and responsive mobile viewport.
3. **Verify BYOD Dry-Run Plan**:
   - Run: `make set-domain ARGS="--domain test.example.com --email admin@example.com --dry-run --skip-dns-check"`
   - Confirms planned `.env` mutations, portal rebuild, and Caddy reload commands without mutating active state.
