## 1. Summary of RC3 Bug Fixes & Architectural Enhancements

| # | Reported Issue | Root Cause & Implemented Fix | Modified Files |
| :- | :--- | :--- | :--- |
| **1** | **Superuser username in First-Boot Wizard defaults to `admin`** | `get_appliance_identity()` in `system.py` fell back to `"admin"` when `BRAINSOS_SUPERUSER_USERNAME` was unset. Updated `system.py` to return `""` when `BRAINSOS_SUPERUSER_USERNAME` is unset or `"admin"`, and updated `SystemManager.tsx` to initialize `setupAdminUsername` to `""` and auto-derive a lowercase slug from **Superuser Full Name** as the operator types (until manually edited), while strictly reserving `admin` for the instance-bound break-glass account. | `packages/brainsOS-telemetry/brainsos_telemetry/system.py`, `packages/brainsOS-portal/src/components/SystemManager.tsx` |
| **2** | **Differentiate Hostname vs. Unit Identity concepts** | Separated **Unit Identity** (`unit_name` / `BRAINSOS_UNIT_NAME`, e.g., `"Enterprise Agent Box"`, paired with read-only Hardware Instance ID `instance_id`) from **Appliance Hostname / FQDN (`local_domain`)** (`<username>.aws.cloud.brainsos.ai`) and **External Web URL (`url`)** in both Wizard Step 2 and the System Overview pane, and added `--unit-name` support to `set-domain.sh`. | `packages/brainsOS-portal/src/components/SystemManager.tsx`, `packages/brainsOS-telemetry/brainsos_telemetry/system.py`, `scripts/control/set-domain.sh`, `scripts/control/generate-env.sh` |
| **3** | **First load after Wizard shows `"Timed out waiting for background job"`, but works on refresh** | When `set-domain.sh --mark-wizard-completed` flipped `BRAINSOS_WIZARD_COMPLETED=true` and reloaded Caddy, `/api/v1/system/jobs/<job_id>` switched from pre-login mode to `authentik_forward_auth`, returning `302` redirects to the unauthenticated browser. Added `@system_public_status` in `Caddyfile` and `Caddyfile.appliance` for `/api/v1/system/jobs/*`, `/api/v1/system/health`, `/api/v1/system/identity`, `/api/v1/system/status`, and `/api/v1/system/csrf`, and updated `pollJobUntilComplete` in `SystemManager.tsx` to resolve immediately as `'success'` once `firstboot_wizard_completed === true`. | `config/caddy/Caddyfile`, `config/caddy/Caddyfile.appliance`, `packages/brainsOS-portal/src/components/SystemManager.tsx` |
| **4** | **Welcome Email gray-on-blue text hard to read under welcome banner** | Brightened the welcome banner subtitle, greeting, intro body copy, and table descriptions in `scripts/control/send-welcome-email.py` from muted gray (`#94a3b8` / `#64748b`) to high-contrast light colors (`#f8fafc`, `#e2e8f0`, `#cbd5e1`). | `scripts/control/send-welcome-email.py` |
| **5** | **Gitea `initial-setup` branch & VS Code `"The extension 'GitHub' wants to sign in using GitHub"` popup** | Updated `scripts/setup/setup-git.sh` to create and push both `main` and `initial-setup` branches to Gitea (`agent-box` repo), use `operator` instead of Gitea-reserved `admin`, configure `branch.main.remote = origin`, `branch.main.merge = refs/heads/main`, and `refs/remotes/origin/main` in `/data/.git/config` so VS Code recognizes `main` as already published (**Sync Changes** instead of **Publish Branch**), and map `X-Authentik-Username: admin` -> `operator` in Caddy `/git/*`. Updated `docker/editor/entrypoint.sh` to set `"github.gitAuthentication": false` and `"git.terminalAuthentication": false` in both user and workspace `settings.json`. | `scripts/setup/setup-git.sh`, `docker/editor/entrypoint.sh`, `config/caddy/Caddyfile`, `config/caddy/Caddyfile.appliance`, `packages/brainsOS-appliance/scripts/firstboot.sh` |
| **6** | **LiteLLM `admin` login lacks full access (`admin` and `su` must both have full access)** | Updated `docker/compose/compose.control.yml` (`PROXY_ADMIN_ID`, `PROXY_ADMIN_EMAILS`), `scripts/setup/setup-litellm-sso.sh`, `scripts/control/reload-env.sh`, and `scripts/control/set-domain.sh` to provision both `admin` and the Superuser (`BRAINSOS_SUPERUSER_USERNAME`) with `user_role: "proxy_admin"` and `models: ["all-proxy-models"]` via LiteLLM REST API and direct PostgreSQL upsert into `"LiteLLM_UserTable"`, with `"default_role": "proxy_admin"` in SSO config. | `docker/compose/compose.control.yml`, `scripts/setup/setup-litellm-sso.sh`, `scripts/control/set-domain.sh`, `scripts/control/reload-env.sh` |
| **7** | **Clicking the new System icon (`#system`) is visible for ~2 seconds and then goes black** | `GET /api/v1/system/status` returns `status.runners` as a dictionary (`{ hermes, claude, openai, tool_keys }`), whereas `SystemManager.tsx` called `status.runners.find(...)`, throwing `TypeError: status.runners.find is not a function` as soon as `/api/v1/system/status` resolved after ~2 seconds. Added `normalizeRunners()` and `extractToolKeys()` in `SystemManager.tsx`, wrapped `SystemManager` in `SystemManagerErrorBoundary`, and accepted `{ keys: {...}, restart_runner: true }` in `POST /api/v1/system/runners/hermes/config`. | `packages/brainsOS-portal/src/components/SystemManager.tsx`, `packages/brainsOS-telemetry/brainsos_telemetry/system.py` |
| **8** | **Full X-Window / XTerm Terminal instead of a command forwarder** | Installed `@xterm/xterm` and `@xterm/addon-fit` in `packages/brainsOS-portal` and replaced the command-forwarder form in `SystemManager.tsx` (`Host Console` pane) with a full interactive **XTerm.js** terminal emulator wired to the live PTY WebSocket (`/api/v1/system/terminal/ws`) with `FitAddon` + `ResizeObserver` (`TIOCSWINSZ`), ANSI color theme, and quick-command toolbar buttons. | `packages/brainsOS-portal/package.json`, `packages/brainsOS-portal/src/components/SystemManager.tsx`, `packages/brainsOS-telemetry/brainsos_telemetry/system.py` |
| **9** | **Local testing broken on `https://dgx.local.brainsos.ai/index.html` (404 on System API, Gitea not working)** | Added `start_system_api`, `stop_system_api`, and `status_system_api` to `scripts/control/start-control-plane.sh` so `make up` / `reload-env.sh` automatically starts the host `brainsos_telemetry.system` daemon on port `8010`, generates/persists `SYSTEM_API_TOKEN` in `.env`, starts `brainsos-app-git` (`gitea`), and seeds `operator/agent-box` with `main` and `initial-setup` branches. | `scripts/control/start-control-plane.sh`, `scripts/control/reload-env.sh` |
