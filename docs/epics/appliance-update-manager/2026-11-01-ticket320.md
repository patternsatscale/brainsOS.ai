## 1. Summary of Changes

During the live AWS EC2 ARM64 (`c7g.xlarge`) rehearsal of the initial candidate AMI (`ami-02071d71608f9157c` on instance `i-03b6fdb651d43c53c`), 10 real-world first-boot, container permission, single-origin SSO, observability routing, and port-binding issues were uncovered, fixed in the repository, verified live on the rehearsal instance, and baked into the updated private Golden AMI (`ami-0a8cfa3e5dd06c081`):

| # | Area | Root Cause Discovered in Live Rehearsal | Fix Implemented | Files Modified |
| :--- | :--- | :--- | :--- | :--- |
| 1 | **Packer Snapshot Sanitization** | GNU `find` rejected `-prune` combined with `-delete` (`The -delete action automatically turns on -depth, but -prune does nothing when -depth is in effect`). | Replaced `-delete` with `-exec rm -f {} +` when paired with `-prune`. | `packages/brainsOS-appliance/packer/provision.sh` |
| 2 | **ClickHouse Cold-EBS First-Boot Healthcheck** | On first boot from a freshly hydrated EBS snapshot, `clickhouse` took >50s to initialize, causing `docker compose up -d` in `brainsos.service` to fail waiting for `dependency_failed`. | Changed ClickHouse healthcheck to `http://127.0.0.1:8123/ping` with `start_period: 60s` and `retries: 15`. | `docker/compose/compose.telemetry.yml` |
| 3 | **Unpublished Host Port Resilience (`start-control-plane.sh`)** | `compose.appliance.yml` unpublishes host ports `4000` (LiteLLM) and `3001` (Langfuse). `start-control-plane.sh` probed `127.0.0.1:4000` and exited with code `7` (`curl` connection refused). | Added `get_container_ip()` and `get_litellm_url()` so health checks, virtual key provisioning, and status probes fall back to the container bridge IP when loopback ports are unpublished. | `scripts/control/start-control-plane.sh` |
| 4 | **Rootless Container Volume Ownership (`UID 1000`)** | `brainsos-firstboot.service` runs as `root`, creating `/opt/brainsos/data/*` owned by `root:root`. Rootless containers (`authentik-server`, `code-server`, `signal-cli`, `runner-hermes`) crashed with `PermissionError: [Errno 13] Permission denied`. | Added `chown -R ${PUID:-1000}:${PGID:-1000}` on non-DB data directories when `bootstrap-env.sh` or `setup-portal.sh` runs as `root`. | `scripts/control/bootstrap-env.sh`, `scripts/setup/setup-portal.sh` |
| 5 | **Signal-CLI Rootless `s6-overlay` Compatibility** | `bbernhard/signal-cli-rest-api:0.101` runs as `USER signal-api` without `setpriv` and blocked indefinitely in `/usr/bin/jsonrpc2-helper`. | Updated `docker/signal/entrypoint.sh` to write `jsonrpc2.yml` directly and launch `signal-cli daemon` in the background before starting `signal-cli-rest-api` and `gateway_proxy.py`. | `docker/signal/entrypoint.sh` |
| 6 | **4 GB Swapfile Provisioning** | `c7g.xlarge` (8 GB RAM) running all 19 appliance containers simultaneously benefited from swap headroom during spike loads. | Added Step 7 in `harden-host.sh` to provision and enable an idempotent 4 GB `/swapfile` (`0600`) persisted in `/etc/fstab`. | `packages/brainsOS-appliance/scripts/harden-host.sh` |
| 7 | **Single-Origin Authentik Host-Only Cookies** | `AUTHENTIK_COOKIE_DOMAIN` defaulted to `local.brainsos.ai` in `compose.apps.yml` and `brainsos-portal.yaml`, causing browsers on `ec2-*.compute-1.amazonaws.com` to drop session cookies (login page reload loop and HTTP `400` on `/outpost.goauthentik.io/callback`). | Set `AUTHENTIK_COOKIE_DOMAIN=` (empty, host-only cookie) on single-origin appliances and updated `compose.apps.yml` (`${AUTHENTIK_COOKIE_DOMAIN-local.brainsos.ai}`), `brainsos-portal.yaml` (`!Env [AUTHENTIK_COOKIE_DOMAIN, ""]`), `firstboot.sh`, `set-domain.sh`, `reload-env.sh`, and `setup-portal.sh`. Also added a readiness wait in `reload-env.sh` before syncing `admin`/`operator` passwords on first boot. | `config/authentik/blueprints/brainsos-portal.yaml`, `docker/compose/compose.apps.yml`, `packages/brainsOS-appliance/scripts/firstboot.sh`, `scripts/control/reload-env.sh`, `scripts/control/set-domain.sh`, `scripts/setup/setup-portal.sh` |
| 8 | **LiteLLM & Langfuse OIDC Secret Sync & RFC-Valid Admin Email** | `firstboot.sh` generated random `AUTH_LITELLM_CLIENT_SECRET` and `AUTH_LANGFUSE_CLIENT_SECRET` in `.env`, but `brainsos-portal.yaml` had hardcoded static defaults (`InvalidClientError`). Additionally, LiteLLM's `fastapi_sso` Pydantic `EmailStr` validator rejected `admin@brainsos.local` (`special-use or reserved name`), returning HTTP `500` on `/sso/callback`. | Passed `AUTH_LITELLM_CLIENT_SECRET` and `AUTH_LANGFUSE_CLIENT_SECRET` to `authentik-server`/`authentik-worker`, referenced them via `!Env` in `brainsos-portal.yaml`, synced them in `reload-env.sh`/`setup-portal.sh`, and changed default admin email from `admin@brainsos.local` to `admin@brainsos.ai`. | `.env.example`, `config/authentik/blueprints/brainsos-portal.yaml`, `docker/compose/compose.apps.yml`, `packages/brainsOS-appliance/scripts/firstboot.sh`, `scripts/control/reload-env.sh`, `scripts/setup/setup-portal.sh` |
| 9 | **Langfuse Single-Origin Routing (Zero Wildcard DNS Required)** | The Portal Trace tab and `NEXTAUTH_URL` pointed to `https://langfuse.${BRAINSOS_DOMAIN}`, which fails with `NXDOMAIN` on default EC2 hostnames (`langfuse.ec2-*.compute-1.amazonaws.com`). | Added single-origin Langfuse route handlers (`/_next/*`, `/project/brainsos*`, `/api/trpc/*`, `/api/auth/*`, `/api/public/*`, `/auth/sign-in*`, `/icon.svg`, etc.) to `Caddyfile.appliance` and `Caddyfile`, narrowed LiteLLM's `/project/*` and `/organization/*` matchers to avoid path collisions, set `NEXTAUTH_URL=https://${BRAINSOS_DOMAIN}`, and updated `ViewportFrame.tsx` to load `${proto}//${host}${port}/project/brainsos/sessions`. | `config/caddy/Caddyfile`, `config/caddy/Caddyfile.appliance`, `docker/compose/compose.telemetry.yml`, `packages/brainsOS-appliance/scripts/firstboot.sh`, `packages/brainsOS-portal/src/components/ViewportFrame.tsx`, `scripts/control/set-domain.sh` |
| 10 | **System Management API Port Collision (`8000` -> `8010`)** | Both `brainsos_agent.worker` (`BRAINSOS_INGRESS_PORT=8000`) and `brainsos-system-api.service` (`BRAINSOS_SYSTEM_API_PORT=8000`) defaulted to `127.0.0.1:8000`. Caddy proxied `/api/v1/system/*` to port `8000`, hitting the queue worker and returning `HTTP 404` in the System Manager UI. | Moved `BRAINSOS_SYSTEM_API_PORT` to `8010` across `system.py`, `firstboot.sh`, `harden-host.sh` (UFW rule allowing `8010/tcp` from `172.16.0.0/12`), `compose.ingress.yml`, `Caddyfile.appliance`, `Caddyfile`, and `.env.example`. | `.env.example`, `config/caddy/Caddyfile`, `config/caddy/Caddyfile.appliance`, `docker/compose/compose.ingress.yml`, `packages/brainsOS-appliance/scripts/firstboot.sh`, `packages/brainsOS-appliance/scripts/harden-host.sh`, `packages/brainsOS-telemetry/brainsos_telemetry/system.py` |
