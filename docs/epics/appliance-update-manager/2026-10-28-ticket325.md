## 2. Acceptance Criteria Verification

### D1. Deployment (Audit #10 API)
- [x] **Console entry point**: `brainsos-system-api` added to `packages/brainsOS-telemetry/pyproject.toml` under `[project.scripts]`. Installed in `.venv` and verified via `.venv/bin/brainsos-system-api --help`.
- [x] **Systemd unit**: `packages/brainsOS-appliance/configs/brainsos-system-api.service` created. Sourced from `/opt/brainsos/.env`. Packer `provision.sh` installs and enables it.
- [x] **Host firewall rule**: `harden-host.sh` adds UFW rule allowing only `172.16.0.0/12` (Docker bridge subnet) to reach port 8000, blocking all external network access.

### D2. AuthN, CORS & CSRF (Audit #4)
- [x] **Wildcard CORS removed**: `CORSMiddleware` completely removed from `create_system_api_app()`.
- [x] **Shared internal secret**: `Caddyfile` and `Caddyfile.appliance` inject `header_up X-BrainsOS-Internal {$SYSTEM_API_TOKEN}`. Requests without it or with invalid tokens get `401 Unauthorized`. `SYSTEM_API_TOKEN` generated automatically via `generate-env.sh`.
- [x] **State-change CSRF & Identity**: State-changing endpoints (`/update`, `/prune-logs`) enforce `X-Authentik-Username`, origin validation, cross-site rejection, and `X-CSRF-Token`. Requests failing checks receive `403 Forbidden`. Ephemeral tokens issued via `GET /api/v1/system/csrf`.

### D3. Execution Robustness (Audit #19)
- [x] **Single-flight lock**: Concurrent update/prune invocations return `409 Conflict` with the active job ID and type.
- [x] **Detached execution & Log persistence**: Jobs execute in detached `asyncio.Task` decoupled from HTTP request lifetime. Logs stream to `data/system_jobs/<id>.log` (under repo runtime dir, preserving Rule 1 memory purity). SSE stream tails the file. Client disconnect does not kill or cancel the job. Added `GET /api/v1/system/jobs/<id>` to query job status/logs and `/stream` to reattach.
- [x] **Service allowlist**: `UpdateRequest.service` validated against declared compose services (`litellm`, `langfuse`, `caddy`, etc.). Unknown services return `400 Bad Request`.

### D4. Honest UI States (Audit #11)
- [x] **Dev-only simulation**: Simulated update and prune logs guarded by `if (import.meta.env.DEV)`.
- [x] **Honest failure reporting**: On API errors, UI displays explicit error message with HTTP status code and remediation hint; execution status transitions to `failed` (never `success`).
- [x] **Status unavailable handling**: When `/status` fails or is unreachable, the UI reports "Status unavailable" instead of showing fabricated `DEFAULT_STATUS` mock data. Update buttons are disabled.
- [x] **CSRF header on POSTs**: UI fetches CSRF token on mount and includes `X-CSRF-Token` on all update and prune requests.

## 4. Local Web Preview & Verification Instructions

- **System Manager Portal**: `https://localhost/system` (or `https://<domain>/system`)
- **API Status Endpoint via Caddy**: `https://localhost/api/v1/system/status`
- **Testing Security Controls**:
  - Direct connection to port 8000 without `X-BrainsOS-Internal`:
    ```bash
    curl -s http://127.0.0.1:8000/api/v1/system/status
    # Returns: 401 Unauthorized
    ```
  - State-change request with evil origin:
    ```bash
    curl -k -X POST -H "Origin: https://evil.example.com" https://localhost/api/v1/system/update
    # Returns: 403 Forbidden
    ```
  - Inspecting a detached job:
    ```bash
    curl -H "X-BrainsOS-Internal: <token>" http://127.0.0.1:8000/api/v1/system/jobs/<job-id>
    ```
