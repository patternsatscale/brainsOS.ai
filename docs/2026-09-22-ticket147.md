## 1. Executive Summary

Ticket #147 migrates in-transit Git Smart HTTP and GitHub API credential injection from the Caddy ingress gateway to the dedicated **Tool Egress Gateway** (`mitmproxy` / `mitmweb`, Ticket #146), establishing strict multi-tenant authorization, native credential masking, and zero-leakage container sandboxing. Additionally, it implements a platform-wide **Docker Container Naming Hierarchy Cleanup**, grouping all containers into distinct architectural namespaces (`titan-agent-*`, `titan-net-*`, `titan-infra-*`, `titan-app-*`, `titan-langfuse-*`).

### Core Architectural Achievements

1. **Dedicated Egress In-Transit Credential Injection Addon (`config/egress/addons/github_auth.py`)**:
   - Intercepts outbound requests to `https://github.com` and `https://api.github.com` on `titan-internal:8082`.
   - Inspects client container source IP identity on `titan-internal` via Docker bridge network mapping.
   - Injects `Authorization: Bearer <GITHUB_TOKEN_CINDY>` for GitHub REST and GraphQL APIs.
   - Injects `Authorization: Basic <GITHUB_BASIC_AUTH_CINDY>` for Git Smart HTTP protocol (`info/refs`, `git-upload-pack`, `git-receive-pack`).
   - Automatically redacts injected tokens to `[INJECTED_CINDY_TOKEN]` within `mitmweb` flow memory and inspection APIs.

2. **Strict Multi-Tenant Isolation & Enforcement (Negative Test Enforcement)**:
   - Only authorized tenant containers (e.g., Cindy Pawford) have credentials injected.
   - Unauthorized tenant containers (e.g., `titan-agent-terrastella`, `titan-agent-football-dan`) attempting to connect to `api.github.com` or `github.com` are strictly rejected with HTTP `403 Forbidden` (`"403 Forbidden: Egress credential injection not permitted for this tenant."`).

3. **Base Image & Workspace Hygiene (Zero URL Rewrites)**:
   - Eliminated fragile Git `insteadOf` rewrites (`git config --system url.https://github-proxy.titan.local/.insteadOf https://github.com/`) from `docker/hermes/Dockerfile` and `sync-agents.sh`.
   - Removed enterprise `GH_HOST=github-proxy.titan.local` overrides. Agents now communicate natively with standard upstream hostnames (`https://github.com` and `https://api.github.com`).
   - Removed obsolete `00-caddy-ca` PKI trust hook and Caddy PKI volume mount (`caddy_data:/etc/ssl/caddy:ro`) from agent containers.
   - Added standard in-transit placeholder configuration in `docker/hermes/Dockerfile` so `gh` CLI commands execute cleanly through the egress proxy with zero ambient tokens in the container filesystem or environment.

4. **Caddy Ingress Purity**:
   - Retired obsolete `github-proxy` reverse proxy blocks (`/api/graphql*`, `/api/v3/*`, `/*`) from `config/caddy/Caddyfile`.
   - Caddy now operates as 100% pure ingress (browser to portals and consoles). All outbound external traffic is governed by the Tool Egress Gateway.

5. **Docker Container Naming Hierarchy Standardization**:
   - Standardized container naming to make the hierarchy immediately readable and navigable:
     - Agents: `titan-agent-terrastella`, `titan-agent-football-dan`, `titan-agent-cindy-pawford`
     - Network: `titan-net-caddy`, `titan-net-egress-proxy`, `titan-net-signal-cli`
     - Infrastructure: `titan-infra-litellm-db` (and `titan-langfuse-db`)
     - Applications: `titan-app-code-server`
   - Retained internal Compose service names and network aliases for 100% backward-compatible internal routing.
