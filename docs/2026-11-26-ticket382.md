### Part B — Warm-Standby Boot Mode, Persistent User EBS Volume Lifecycle, Stateful Volume Bind Mounts & Proxy-Friendly Portal
- **Created**:
  - [`packages/brainsOS-appliance/scripts/claim-user-volume.sh`](../packages/brainsOS-appliance/scripts/claim-user-volume.sh) & [`scripts/control/claim-user-volume.sh`](../scripts/control/claim-user-volume.sh): SSM-invocable volume claim tool supporting `--device` (auto-detecting non-root Nitro NVMe / `xvd*` EBS devices), `--mount` (`/mnt/brainsos-data`), `--domain`, `--user-sub`, and `--skip-portal-rebuild` (default `true`). Formats `ext4` **only** when fail-closed `blkid` + `blkid -p` checks prove the device has zero filesystem or partition signatures, mounts with `noatime`, handles both first-time (`firstboot.sh --claim`) and returning user volumes (preserving all DB/service passwords while updating host IMDSv2/domain metadata via `env-upsert.sh`), starts `brainsos-system-api.service` + `brainsos.service`, and polls local `:443` readiness.
  - [`packages/brainsOS-appliance/scripts/release-user-volume.sh`](../packages/brainsOS-appliance/scripts/release-user-volume.sh) & [`scripts/control/release-user-volume.sh`](../scripts/control/release-user-volume.sh): Cleanly stops `brainsos.service` (`docker compose down`) + `brainsos-system-api.service`, verifies zero running containers retain mounts under `/mnt/brainsos-data`, removes `/opt/brainsos/.env` and `/opt/brainsos/.brainsos-initialized` symlinks, flushes kernel buffers (`sync`), and unmounts `/mnt/brainsos-data` prior to `ec2:DetachVolume`.
  - [`packages/brainsOS-appliance/tests/test_warm_standby_ebs.py`](../packages/brainsOS-appliance/tests/test_warm_standby_ebs.py): 8 automated tests covering `BRAINSOS_WARM_STANDBY=true` / `warm_standby: true` user-data, standalone backwards compatibility, symlink-preserving `.env` updates, real `ext4` `.img` formatting + `blkid` UUID preservation across simulated Host A -> release -> Host B rotations, fail-closed MBR partition-table protection, `:443` TLS health-gate polling, and Packer snapshot hygiene.
- **Modified**:
  - [`packages/brainsOS-appliance/scripts/firstboot.sh`](../packages/brainsOS-appliance/scripts/firstboot.sh), [`configs/brainsos.service`](../packages/brainsOS-appliance/configs/brainsos.service), [`configs/brainsos-firstboot.service`](../packages/brainsOS-appliance/configs/brainsos-firstboot.service), & [`packer/provision.sh`](../packages/brainsOS-appliance/packer/provision.sh): Added `BRAINSOS_WARM_STANDBY=true` (`warm_standby: true`) warm-pool mode, `--mount-root` / `--claim` / `--domain` / `--user-sub` support, `Wants=brainsos-system-api.service` on `brainsos.service`, and symlink-aware snapshot scanning.
  - [`scripts/control/env-upsert.sh`](../scripts/control/env-upsert.sh), [`scripts/control/generate-env.sh`](../scripts/control/generate-env.sh), & [`scripts/control/bootstrap-env.sh`](../scripts/control/bootstrap-env.sh): Made `.env` writes `os.path.realpath()`-aware so atomic rewrites update `/mnt/brainsos-data/.env` in place without breaking `/opt/brainsos/.env` symlinks or raising `EXDEV`.
  - [`docker-compose.yml`](../docker-compose.yml), [`docker/compose/compose.agents.yml`](../docker/compose/compose.agents.yml), [`docker/compose/compose.ingress.yml`](../docker/compose/compose.ingress.yml), [`docker/hermes/01-tool-egress-ca`](../docker/hermes/01-tool-egress-ca), [`scripts/control/reload-env.sh`](../scripts/control/reload-env.sh), & [`scripts/setup/trust-caddy-ca.sh`](../scripts/setup/trust-caddy-ca.sh): Migrated `hermes_runner_data` (`${BRAINSOS_DATA_DIR}/runners/hermes/state:/opt/data`) and `caddy_data` (`${BRAINSOS_DATA_DIR}/control_plane/caddy_data:/data`) from `/` Docker named volumes to `${BRAINSOS_DATA_DIR}` bind mounts (with automatic one-time upgrade migration), leaving only ephemeral `caddy_config` and `tool_egress_proxy_data` on `/`.
  - [`scripts/setup/setup-portal.sh`](../scripts/setup/setup-portal.sh), [`packages/brainsOS-portal/src/App.tsx`](../packages/brainsOS-portal/src/App.tsx), [`SubsystemsDrawer.tsx`](../packages/brainsOS-portal/src/components/SubsystemsDrawer.tsx), [`HelpView.tsx`](../packages/brainsOS-portal/src/components/HelpView.tsx), [`subsystems.ts`](../packages/brainsOS-portal/src/data/subsystems.ts), [`.env.example`](../.env.example), & [`README.md`](../README.md): Kept the pre-built Portal SPA 100% reverse-proxy friendly without runtime Vite rebuilds (`VITE_APPLIANCE_HOST=""` when built on `localhost`, relative `./assets/` paths, dynamic `window.location.hostname`, single-origin telemetry URLs without `langfuse.${host}` subdomain rewrites, and dynamic `Alt+4` routing to `/proxy/ui/?page=lens` when `telemetry_backend=lens`).

## 2. Acceptance Criteria Verification

- [x] **Vendor-Neutral Telemetry SPI (`brainsOS-telemetry`)**: `BRAINSOS_TELEMETRY_BACKEND=dual|lens|langfuse|none` governs worker, Hermes, OpenAI/Claude SDK runners, LiteLLM patch, System API, Portal `Alt+4`, and CLI URL directory from one canonical OTLP GenAI module.
- [x] **`BRAINSOS_WARM_STANDBY=true` Boot Mode (100% Backwards-Compatible)**: Warm-standby instances exit `firstboot.sh` `0` cleanly without creating `.env`, seeding `data/`, touching `.brainsos-initialized`, or starting `brainsos.service`; standalone boots remain unchanged.
- [x] **Persistent `.env` & `.brainsos-initialized` on User Volume (`BRAINSOS_MOUNT_ROOT`)**: Stored on `/mnt/brainsos-data/{.env,.brainsos-initialized,data}` and symlinked from `/opt/brainsos/`, with `realpath`-safe atomic `.env` updates across `env-upsert.sh`, `generate-env.sh`, and `bootstrap-env.sh`.
- [x] **`claim-user-volume.sh` & `release-user-volume.sh`**: Verified first-time `ext4` formatting (`blkid` fail-closed), `noatime` mount, `BRAINSOS_FIRSTBOOT_SKIP_PORTAL=true` fast claim, returning-volume DB password preservation across hosts, `:443` readiness gate, and clean `docker compose down` + `sync` + `umount`.
- [x] **Docker Named Volume Audit**: `hermes_runner_data` and `caddy_data` moved under `${BRAINSOS_DATA_DIR}`; only ephemeral `caddy_config` and `tool_egress_proxy_data` remain named volumes on `/`.
- [x] **Proxy-Friendly Pre-Built Portal Bundle**: `tsc && vite build` produces relative `./assets/*` bundles with zero baked `localhost` hostnames or subdomain rewrites.
