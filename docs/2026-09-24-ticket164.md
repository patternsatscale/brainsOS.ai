## 1. Executive Summary & Architectural Alignment

Ticket #164 establishes native, autonomous email communications for the Project Titan agent fleet (`terrastella@titan.local`, `marvin@titan.local`, `bawtford@titan.local`) under a strict **Tool-First Model**:
1. **Split-Brain & Token Runaway Prevention**: Automatic chat platform auto-reply gateways (`platforms.email.enabled: false`) are disabled across all agents, preventing duplicate LLM generation turns, context thrashing, and unconstrained completion loops.
2. **Doorbell Push-Wakeup**: Inbound emails arriving at Postfix (`mail-server:25`) are handed off via LMTP (`127.0.0.1:24`) to Dovecot MDA. Dovecot Pigeonhole Sieve triggers `/etc/dovecot/sieve/default.sieve` (via `sieve_before`), piping RFC 822 messages to `/usr/lib/dovecot/sieve-pipe/agent-webhook.sh`. The script parses headers (`To`, `From`, `Subject`, `Message-ID`, `In-Reply-To`, `Date`) into JSON, maps the recipient to the target agent container port (`8642`, `8643`, `8644`), and issues an HTTP `POST /webhook` without polling.
3. **Explicit Agent Tool Actions**: Agents actively query and respond using native `titan-mail` tools:
   - `search_emails`: Searches IMAP folders by query, subject, sender, and unread status.
   - `read_email`: Retrieves parsed message bodies and threading references (`Message-ID`, `In-Reply-To`, `References`).
   - `send_email`: Sends outbound emails via Postfix SMTP.
4. **Multi-Tenant Sender Verification**: Agents are strictly locked to their assigned identities (`{agent_id}@titan.local`). Any attempt by an agent to forge or spoof an alternate sender address is rejected before network transmission.
5. **Memory Plane Purity (Rule 1)**: Inbound notifications write strictly to `/memories/logs/email_inbound.md` in human-auditable Open Knowledge Format (OKF) Markdown; zero databases or binary caches are permitted in `/memories`.

## 5. Clean Two-Tier Key Architecture & Hardware Serialization

We eliminated legacy fallbacks (`HERMES_LITELLM_KEY`, `HERMES_MARVIN_KEY`, `HERMES_BAWTFORD_LITELLM_KEY`, shared `API_SERVER_KEY`) in favor of an explicit two-tier taxonomy:

1. **Inbound Fleet Agent Gateway Keys (`HERMES_API_<AGENT>_KEY`)**:
   - `HERMES_API_TERRASTELLA_KEY`, `HERMES_API_MARVIN_KEY`, `HERMES_API_BAWTFORD_KEY`.
   - Used by webhooks (`agent-webhook.sh`), Operator IDE (`continue_config.yaml`), CLI (`titan-chat`), and external callers connecting to `api.<agent>.titan.local`.
   - Injected into each agent container as `API_SERVER_KEY` for upstream Hermes FastAPI enforcement.

2. **Outbound LiteLLM Control Plane Virtual Keys (`<AGENT>_LITELLM_KEY`)**:
   - `TERRASTELLA_LITELLM_KEY`, `MARVIN_LITELLM_KEY`, `BAWTFORD_LITELLM_KEY`, `OPERATOR_LITELLM_KEY`.
   - Seeded in LiteLLM DB (`LiteLLM_VerificationToken`) with monthly budgets and rate limits.
   - Injected into each agent container as `OPENAI_API_KEY` for outbound model inference routing to `http://proxy.local:4000/v1`.

3. **Concurrency & Hardware Serialization (Rule 3)**:
   - **Global Model Serialization**: Hardware serialization (`max_parallel_requests: 1`) is configured at the **model deployment level** in `config/litellm/config.yaml`, protecting the unified LPDDR5x memory bus across the entire fleet regardless of which virtual key or agent submits a request.
   - **Independent Virtual Keys**: Agents do **NOT** need to share a virtual key to enforce concurrency. Retaining unique virtual keys per agent preserves per-tenant spend tracking, Langfuse trace attribution, and targeted emergency stop capabilities.

4. **Caddy Ingress Alignment**:
   - Resolved `*.titan.local` routing in `config/caddy/Caddyfile` with `tls internal` to ensure `proxy.titan.local`, `editor.titan.local`, `mail.titan.local`, etc. work identically on LAN and `/etc/hosts` even when `TITAN_DOMAIN` points to an external domain.
