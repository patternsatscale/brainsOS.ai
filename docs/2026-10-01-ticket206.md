## 1. Executive Summary

**Epic #206** delivers production-grade, secure, external inbound email ingress to the **brainsOS** autonomous agent fleet. Operating under **Rule 4 (Host Sandboxing & Outbound Polling)**, brainsOS development workstations and edge GX10 appliances run with **zero open inbound firewall ports, zero public webhooks, and zero fragile tunneling services (ngrok/Cloudflare Tunnels)**.

Instead, the architecture implements an **asynchronous S3 Claim-Check pattern over AWS SQS**, safeguarded by an automated **5-Stage Defensive Security Sanitizer Lambda**:
1. External emails sent from verified operators (e.g. `patternsatscale@gmail.com`) to any fleet agent (e.g. `ping@osx.public.brainsos.ai`, `bawtford@osx.public.brainsos.ai`, `claude@osx.public.brainsos.ai`) are accepted by Amazon SES via Route 53 MX, Easy DKIM, SPF, and DMARC records.
2. SES writes raw RFC 822 MIME streams directly to an S3 staging bucket (`raw/`).
3. An AWS Lambda trigger subjects incoming messages to a rigorous 5-stage defensive gate:
   - Cryptographic DKIM/SPF/DMARC authentication.
   - Strict sender allowlist enforcement.
   - Unicode, zero-width space, and hidden HTML tag stripping.
   - Heuristic prompt injection scanning.
   - Safe isolation enveloping (`<<<EXTERNAL_UNTRUSTED_CONTENT>>>`).
4. Approved claim-check descriptors are published to an SQS FIFO/Standard queue. Malicious or spoofed messages are quarantined with zero notification sent to SQS.
5. An unprivileged, sandboxed Docker container (`brainsos-net-mail-ingress`) polls SQS via outbound HTTPS, resolves claim checks, reconstructs RFC 822 MIME payloads, and injects them into the local Postfix mail engine (`brainsos-net-mail-server:25`).
6. Dovecot delivers to the agent's Maildir, triggers Sieve hooks, and streams into `AgentQueueWorkerDaemon`.
7. The worker routes cognitive turns through unified warm stateless runner microservices (`RunnerMailAdapter` -> `/v1/agent/run`), records dialogue in pure OKF Markdown, and replies autonomously via Amazon SES with verified public identity alignment.

## 5. Summary of System Modifications

1. **Infrastructure as Code (`infra/`)**:
   - Modularized into Pulumi-native SST components (`components/` and `flows/`).
   - Dynamically scoped Easy DKIM, MX, SPF, and DMARC TXT records strictly to ingress subdomains (`${stage}.public.brainsos.ai`) to eliminate Route 53 record collision with the apex domain.
   - Configured `ActiveReceiptRuleSet` to guarantee receipt rules are activated immediately upon deployment.
   - Exported `bucketPolicy` and wired strict `dependsOn` relationships, eliminating S3/SES race conditions.
2. **Mail Plane (`packages/brainsOS-mail/`)**:
   - Built standalone `brainsos_mail.ingress` submodule supporting S3 claim-check downloads, SQS long-polling, RFC 822 MIME reconstruction, and local SMTP injection.
   - Added `_send_via_ses()` to `BrainsOSMailClient` using `boto3` raw email dispatch for external destinations.
3. **Agent Runtime Plane (`packages/brainsOS-agent/`)**:
   - Unified all LLM agent runtimes (`hermes`, `openai`, `claude`, and dynamic `runner:<id>`) through `RunnerMailAdapter`, calling the universal IPC endpoint (`/v1/agent/run`) on warm runner microservices.
   - Added `resolve_manifest_path()` respecting decoupled fleet repositories (`BRAINSOS_DATA_DIR`) per Rule 14.
   - Added RFC 5322 `Message-ID` deduplication and single-spool file reuse, completely eliminating dual-ingestion race conditions between Dovecot Sieve webhooks and background filesystem scanners.
   - Automatically binds outbound SES From headers to the verified public domain identity (`BRAINSOS_EMAIL_DOMAIN`).
4. **Local Mail Topology (`docker/mail/`)**:
   - Added unprivileged container `brainsos-net-mail-ingress` with read-only rootfs and ephemeral tmpfs.
   - Configured Postfix in `brainsos-net-mail-server` to accept local injection for virtual domains while strictly denying open relay.
   - Provisioned all fleet agent mailboxes (`terrastella`, `marvin`, `bawtford`, `ping`, `claude`, `gpt`) and virtual aliases (`cindy@... -> bawtford@...`).
5. **Verification & Developer Tooling (`scripts/` & `Makefile`)**:
   - Codified `scripts/verify/verify-email-ingress.sh` automating health checks, sanitizer unit tests, package unit tests, the TC-01 through TC-06 scenario matrix, and Rule 1 memory purity audits.
   - Added developer convenience targets: `make email-ingress` and `make email-test`.

## 9. Inviolable Architectural Guardrails Compliance

| Guardrail | Enforcement Mechanism | Compliance Verdict |
| :--- | :--- | :---: |
| **Rule 1: Memory Plane Purity** | S3 and local spool directories remain completely separate from `/memories`. Automated purity audit in Step 6 asserts zero MIME or DB artifacts in agent memory stores. | **PASSED** |
| **Rule 2: Inference Boundary** | Runners route cognitive turns strictly through LiteLLM gateway (`:4000/v1`) using master key authentication. Direct container access to raw Ollama daemon is barred. | **PASSED** |
| **Rule 4: Host Sandboxing & Outbound Polling** | Zero inbound firewall ports or tunneling daemons opened on local network. Ingress worker operates purely on outbound HTTPS polling to AWS SQS and S3. | **PASSED** |
| **Rule 5: Secret Protection** | AWS access keys, SQS URLs, and SES secrets are strictly loaded via `.env` and `.env.example`. Zero sensitive secrets committed to Git repository. | **PASSED** |
| **Rule 7: Information Compartmentalization** | Quarantine failure traces and prompt injection signatures remain isolated in S3 `/quarantine/` and are never reflected into agent cognitive context. | **PASSED** |
| **Rule 8: Script-Driven Discipline** | Zero ad-hoc container patching. All setup, verification, and deployment codified in `scripts/verify/verify-email-ingress.sh`, `scripts/setup/setup-mail.sh`, and `Makefile`. | **PASSED** |
| **Rule 10: In-Transit Egress Credential Injection** | Outbound agent HTTP requests route through egress inspection proxy (`:8082`), masking secrets and validating client container identity. | **PASSED** |
| **Rule 14: Decoupled Fleet Isolation** | Platform core resolves data paths dynamically via `BRAINSOS_DATA_DIR`, supporting private fleet repositories without code modification. | **PASSED** |
