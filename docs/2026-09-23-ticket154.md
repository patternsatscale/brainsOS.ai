## 1. Executive Summary

This deliverable resolves the end-to-end telemetry propagation gap between the **Agent Plane (Hermes)**, **Control Plane (LiteLLM Gateway)**, and **Observability Plane (Langfuse v4.38.0)**. 

Prior to this change, Langfuse ran in `events_only` write mode which disabled the `/api/public/sessions` endpoint and rejected legacy batch events from LiteLLM's Langfuse logger. Consequently, all ingested traces lacked a `sessionId` (appearing as `NULL` in ClickHouse and PostgreSQL) and could not be grouped into user sessions or conversational replays.

With this implementation:
1. **Langfuse `dual` Write Mode Activated**: Both PostgreSQL and ClickHouse receive telemetry events, enabling the REST `/api/public/sessions` and `/api/public/traces` endpoints and unlocking the full Langfuse **Users** and **Sessions** dashboard views.
2. **3-Tier Hierarchy Enforced (Titan &rarr; Agent &rarr; AgentSession)**:
   - **Titan (Project Scope)**: Global workspace context.
   - **Agent (`User` / `userId`)**: Bound dynamically via LiteLLM virtual keys (`user_id: <agent_id>`) and request body (`user: <agent_id>`). Each agent breaks out into the **Users** tab with aggregate cost, tokens, latencies, and session lists.
   - **AgentSession (`Session` / `sessionId`)**: Standardized as `titan-<agent_id>-<context_id>`, propagated via `x-litellm-session-id` HTTP header and `metadata.session_id`. Each session breaks out into the **Sessions** tab with full trace trees and turn replay.
3. **Metadata & Multi-Dimensional Tags Preserved**: Trace metadata carries full execution parameters (`agent_id`, `model`, `plane: agent`, `test_id`), while multi-attribute tags (`[<agent_id>, "titan", "verification"]`) enable rapid UI filtering.
4. **Hermes Telemetry Request Middleware**: Registered in `docker/hermes/plugins/hermes-okf/__init__.py` to automatically inject session headers, identity, and metadata into all outgoing agent completions.
