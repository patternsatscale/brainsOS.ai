### 1.3 Clean XTerm PTY Startup & Decoupled System Job Output
- **[`packages/brainsOS-telemetry/brainsos_telemetry/system.py`](../packages/brainsOS-telemetry/brainsos_telemetry/system.py)** & **[`packages/brainsOS-telemetry/tests/test_system_api.py`](../packages/brainsOS-telemetry/tests/test_system_api.py)**:
  - Set `HUSHLOGIN=TRUE` in the PTY environment and spawned the shell with `["--norc", "--noprofile", "-i"]` so `/etc/profile` and `~/.bashrc` MOTD/banner noise does not clutter the terminal buffer.
  - Emitted `\x1b[2J\x1b[H` (ANSI clear screen + cursor home) immediately upon PTY connection before writing the clean `brainsOS Interactive Host Shell (PTY)` header.
- **[`packages/brainsOS-portal/src/components/SystemManager.tsx`](../packages/brainsOS-portal/src/components/SystemManager.tsx)**:
  - Added `term.reset()` and `term.clear()` on XTerm initialization and inside `ws.onopen`, plus a **Clear Terminal** button in the terminal header.
  - Decoupled `executeConsoleCommand` from `xtermRef.current` so System Job Output (`consoleEntries` / `logs`) never echoes into the interactive XTerm PTY, eliminating cross-talk between background job output and the interactive shell.
